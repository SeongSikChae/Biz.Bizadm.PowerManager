# R01 장치 등록과 접속 조회

## 목적

장치가 PowerManager 서버에 등록해 MQTT 접속 키를 받으려 한다. 서버는 장치 등록(`POST /api/v1/devices/register/create`)에 장치별 `mqtt_key`를 발급해 SQLite(EF Core)에 저장하고, 장치가 그 키를 받아들이게 하는 `verify`를 계산해 응답한다. 장치의 접속 조회(`GET /api/v1/device/connect/{deviceKey}`)에 답하고, 관리자가 정한 장비명을 같은 저장소에 둔다.

## 요구사항

| ID | 요구사항 | 상태 | 일감 |
| --- | --- | --- | --- |
| `R01-R1` | 올바른 등록 요청을 받으면 서버는 200과 `application/json` 본문 `{"verify":"<44자>","mqtt_key":"<키>"}`를 반환한다. 키는 이 두 개뿐이고 `verify`가 `mqtt_key`보다 앞이다. | 반영 | |
| `R01-R2` | 서버는 새로 발급하는 `mqtt_key`를 암호학적 난수로 만든 16자로, 문자는 `[A-Za-z0-9]`에서만 고른다. | 반영 | |
| `R01-R3` | 서버는 `verify`를 치환표 `XGAqW.Ibj3xdCRFzf60oMKNDYPaTQHLUhls4v1mei5S9w-r8n=kJtV/O+7ZEu2cgypB`(67자)로, `s = DeviceMqttServerAddr + mac(소문자)`, `k = mqtt_key`에 대해 i = 0..43마다 `A[(pos(s[i mod \|s\|])·sum(k) + pos(k[i mod \|k\|])·sum(s)) mod 67]`로 계산한다. `DeviceMqttServerAddr`(기본 `dwmqtt.dawonai.com`)는 장치에 설정된 `server_addr`와 같아야 하며, 치환표 문자로만 이뤄지지 않으면(빈 값 포함) 서버는 시작할 때 설정 오류로 끝난다. | 반영 | |
| `R01-R4` | `device.mac`이 12자리 16진수가 아니면(없거나 빈 값 포함) 서버는 400 ProblemDetails를 반환하고 저장하지 않는다. 서버는 mac을 소문자로 정규화하고, `account.user_id`·`device.model_id`·`device.company`가 없거나 빈 값이어도 거부하지 않는다. | 반영 | |
| `R01-R5` | 서버는 발급한 키를 mac별로 SQLite(`DatabasePath`, 기본 `powermanager.db`, `ContentRootPath` 기준)에 저장한다(mac, user_id, model_id, company, mqtt_key, 처음 등록 시각, 마지막 요청 시각, 장비명(`R01-R9`, 없으면 빈 문자열)). 처음 등록 때 없는 값은 빈 값으로 저장한다. 서버는 시작할 때 마이그레이션을 적용하며, 재시작해도 값이 남는다. | 반영 | #32 |
| `R01-R6` | 이미 저장된 mac으로 다시 등록 요청이 오면 서버는 저장된 키로 응답하고(`verify`는 현재 설정으로 다시 계산), 마지막 요청 시각을 갱신하며, user_id·model_id·company는 비어 있지 않은 값이 왔을 때만 바꾸고, 장비명은 바꾸지 않는다. 같은 mac의 첫 등록이 동시에 들어오면 저장된 키 하나로 응답한다. | 반영 | #32 |
| `R01-R7` | 서버는 로그에 `mqtt_key`와 `verify` 값을 남기지 않는다. | 반영 | |
| `R01-R8` | 접속 조회를 받으면 서버는 `deviceKey`가 `DAWONDNS-{모델}-{mac}`(모델은 비어 있지 않고 `-` 포함 가능, mac은 마지막 `-` 뒤 12자리 16진수)이고 그 mac(대소문자 무관)이 등록돼 있으면 200 `{"delay":"0"}`, 아니면 404 ProblemDetails를 반환한다. | 반영 | |
| `R01-R9` | 관리 포트에서 `PUT /api/admin/devices/{mac}/name`을 받으면 서버는 본문 `{"name":"<장비명>"}`의 앞뒤 공백(.NET `char.IsWhiteSpace`가 참인 문자)을 없앤 값을 저장하고 204를 반환한다. 없앤 값이 빈 문자열이면 장비명을 지운다. 같은 장비명을 여러 장비에 쓸 수 있다. 실패는 ProblemDetails이고 저장하지 않으며, 판정 순서는 mac 형식(400) → 등록(404) → 장비명(400)이다. 장비명이 없거나 null이거나, 없앤 값의 길이(UTF-16 코드 단위)가 30을 넘거나, 제어 문자·줄 구분 문자(U+2028·U+2029 포함)가 들어 있으면 400이다. 장치 포트에서는 404 ProblemDetails다(`admin/R01-R6`). 장비명을 바꿔도 다른 값(마지막 요청 시각 포함)과 장치 응답은 바뀌지 않고, 바뀌었을 때만 상태 스트림(`admin/R04-R6`)으로 알린다. | 반영 | #32 |

## 지금 동작

- `verify` 계산식은 B540 펌웨어 분석으로 찾았고, 실제 다원 서버 응답과 일치함을 확인했다.
- 서버 설정 YAML은 기본 `YamlDotNet.Serialization.Deserializer`로 읽어 모르는 키에서 실패한다(`src/Biz.Bizadm.PowerManager.Server.Spa/Program.cs`의 `RunAsync`). 그래서 제거된 중계 모드의 `DawonRelay` 섹션이 남은 설정으로는 서버가 설정 오류(종료 코드 2)로 시작하지 않는다(`T01_03`에서 확인).
- 장비명 저장 API는 관리 API지만 장비명이 등록 저장소의 열이라 이 스펙에 둔다. 장비명을 보이고 바꾸는 화면은 `admin/R04-R25`다.
