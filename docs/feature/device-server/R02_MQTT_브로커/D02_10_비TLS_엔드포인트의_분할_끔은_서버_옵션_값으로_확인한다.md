# D02_10 비TLS 엔드포인트의 분할 끔은 서버 옵션 값으로 확인한다

## 상황

spec 검토 1회차 지적 4. C2("C1과 같은 설정")는 무엇을 확인하면 충족되는지 정해져 있지 않고, 비TLS에서는 TCP가 조각을 합치거나 나눌 수 있어 수신 관찰로 쓰기 횟수를 판정하기 어렵다. 서버 옵션은 지금 `StartAsync` 안에서 만들어져 밖에서 확인할 수 없다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C2(`docs/specs/mqtt-no-fragmentation/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_07`

## 결정

- A. 옵션 값으로 확인: C2를 "브로커가 만드는 MQTT 서버 옵션에서 비TLS·TLS 엔드포인트 모두 `AllowPacketFragmentation`이 false"로 바꾸고 테스트에서 옵션 값을 확인한다.

## 이유

- A는 결정적으로 확인할 수 있고, 비TLS 경로도 TLS와 같은 송신 코드(`MqttChannelAdapter`)를 쓰므로 설정이 맞으면 동작이 같다. B는 TCP가 두 쓰기를 한 세그먼트로 합칠 수 있어 분할이 켜진 상태에서도 테스트가 통과할 수 있다(결정적이지 않음). 고치지 않으면 코드를 읽는 것 말고는 완료를 판정할 수 없다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| --- | --- |
| B. 비TLS 수신 관찰: C2를 "비TLS 엔드포인트에서 원시 TCP 클라이언트가 PUBLISH 전체를 한 번의 수신으로 받는다"로 바꾼다. | 위 「이유」에 함께 적힘 |
