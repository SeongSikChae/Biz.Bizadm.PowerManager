# D02_18 C3·C4의 MQTT 3.1.1 확인은 tasks.md에만 더한다

## 상황

tasks 검토 1회차 지적 1. 검토 의견: spec C3·C4는 MQTT 3.1·3.1.1 클라이언트가 반환 코드 4·3을 받는다고 정하는데, 3.1.1(V311) 클라이언트 확인은 C2(틀린 비밀번호)에만 있고 C3(`Unknown`)·C4(예외)에는 없다. MQTTnet의 반환 코드 변환은 패키지 소스로 확인하지 못한 전제라, `ServerUnavailable`이 3.1.1에서 3으로 나가는지 확인하지 않은 채 완료로 처리되므로 문제다.

- 정한 단계: tasks
- 관련: 옛 작업 스펙의 tasks.md T002, T003(`docs/specs/mqtt-connect-auth/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_09`

## 결정

- A. tasks만 고침: T002 미등록 mac 경우에 V311 클라이언트 → `BadUserNameOrPassword`, T003에 V311 클라이언트 → `ServerUnavailable`을 더한다. 확인받은 plan.md는 바꾸지 않는다.

## 이유

- A는 spec이 이미 요구하는 확인을 채울 뿐 설계를 바꾸지 않아 tasks 두 줄로 끝난다. B는 문서 사이가 가장 잘 맞지만, 테스트 경우 둘을 더하려고 plan 검토·확인을 다시 하는 절차 비용이 커 고르지 않았다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안
