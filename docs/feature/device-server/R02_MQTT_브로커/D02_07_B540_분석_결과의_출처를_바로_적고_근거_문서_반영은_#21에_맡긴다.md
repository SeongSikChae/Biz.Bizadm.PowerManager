# D02_07 B540 분석 결과의 출처를 바로 적고 근거 문서 반영은 #21에 맡긴다

## 상황

spec 검토 2회차 지적 1. 검토 의견: 「무엇을, 왜」가 B540의 세 항목(접속 직후 QoS 0 구독, 받은 메시지 토픽 무검사, 응답 형식 `n`·`sv`가 해석 경로에 맞음)의 근거로 `docs/reference/b540-mqtt-topic.md`를 들었지만, 그 문서는 QoS를 "토픽별 QoS 값은 미확인", `sv`를 "수신 파서에서 확인하지 못했다(추정)"로 적고 토픽 무검사는 적지 않았다. 세 항목은 #21 실장비 확인 뒤 B540 슬롯 B를 다시 디컴파일한 결과로, 저장소 밖 작업 기록에만 있다. 저장소만 보는 사람은 "확인했다"와 반대되는 서술을 보게 되는 것이 문제다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 무엇을·왜(`docs/specs/mqtt-subscribe-log/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_06`

## 결정

- A. 인용 바꾸기: spec에서 근거 문서 인용을 빼고 "#21 실장비 확인 뒤 다시 분석(B540 1.01.34 슬롯 B 재디컴파일, M130-W 2.01.58 분석)해 확인했고, 근거 문서에는 아직 반영하지 않았으며 #21의 근거 문서 반영 작업에서 적는다"로 적는다.

## 이유

- A를 고른 이유는 근거 문서 반영이 원래 #21의 작업(T011)이라 이 작업(로그 추가) 범위를 키우지 않으면서 인용과 내용이 어긋나는 문제를 없애기 때문이다. 저장소 밖 작업 기록 경로는 저장소 내용 규칙상 spec에 적지 않는다. B는 #21 T011과 겹치고 이 작업 범위를 키워 고르지 않았다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
