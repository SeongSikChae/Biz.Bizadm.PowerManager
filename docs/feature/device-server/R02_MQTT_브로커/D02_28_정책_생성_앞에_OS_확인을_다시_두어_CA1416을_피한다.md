# D02_28 정책 생성 앞에 OS 확인을 다시 두어 CA1416을 피한다

## 상황

plan 검토 2회차 지적 1(회귀). 검토 의견: `D02_26`(옛 D007)대로 OS 판단을 `ResolveCipherSuites`의 인자로만 넘기고 "목록이 있을 때만 `CipherSuitesPolicy`를 만든다"로 짜면, `CipherSuitesPolicy` 형식에 `[UnsupportedOSPlatform("windows")]`가 붙어 있어 플랫폼 분석기가 Windows 보호를 보지 못하고 CA1416을 낸다. 왜 문제인지: C5의 `dotnet build -warnaserror`가 실패한다(검토자가 같은 설정의 시험 프로젝트로 재현, 저장소에 CA1416 끄는 설정 없음).

- 정한 단계: plan
- 관련: 옛 작업 스펙의 plan.md 바꿀 파일·구조(ServerKestrelExtensions.cs), 결정, 원칙 점검(`docs/specs/mqtts-tls-policy/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_10`

## 결정

- A. 생성 앞 보호 구문: `ResolveCipherSuites(…, OperatingSystem.IsWindows())`를 부른 뒤 `if (suites is null || OperatingSystem.IsWindows()) return null;` 뒤에서만 정책을 만든다. 원칙 점검에 둘째 확인은 분석기용 보호 구문이라고 적는다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| C. CA1416 경고 끄기: `#pragma warning disable CA1416`. | 사용자가 말하지 않음 |
