# D02_31 작업 PC의 TLS 1.0·1.1 핸드셰이크 테스트는 두지 않는다

## 상황

plan 검토 4회차 지적 2. 검토 의견: 검증 C1의 "`SslStream`으로 TLS 1.0·1.1은 성공하지 않는지 확인"(tasks T005)은 클라이언트에 `SslProtocols.Tls`·`Tls11`을 지정해야 하는데 .NET 10에서 사용 중단이라 SYSLIB0039 경고가 나고 `-warnaserror`에서 오류가 된다(검토자가 시험 프로젝트에서 재현, 저장소에 억제 설정 없음). 왜 문제인지: 단계 2 체크포인트와 C5 빌드가 실패한다. 또 클라이언트(Windows)가 TLS 1.0·1.1을 막을 수 있어 이 테스트는 서버 동작을 가리지 못한다.

- 정한 단계: plan
- 관련: 옛 작업 스펙의 plan.md 요약·오류·위험 넷째 항목·검증 전략 C1, tasks.md T005(`docs/specs/mqtts-tls-policy/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_10`

## 결정

- A. PC의 1.0·1.1 테스트 빼기: 검증 C1에서 빼고 TLS 1.0·1.1 거절은 C6의 `openssl` 판정으로만 확인한다. 오류·위험 넷째 항목과 tasks T005도 맞춘다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
