## 할 일

### 단계 1: 루트 파일 (U1)
- 기존 파일에 필요한 항목만 더한다.

확인: DeviceConfig 프로젝트가 `.slnx`에 남고 패키지 항목 5개 추가.

### 단계 2: Server.Core (U2)
- 설정 검사·KMS·로깅·여러 포트 Kestrel·TLS.

확인: `dotnet test --project tests/Biz.Bizadm.PowerManager.Server.Core.Tests` 통과(`KestrelTlsTests` 포함).

### 단계 3: Core 도메인 (U3)
- `DeviceTopic.TryParse`·`ToDevice`, `MqttEnvelope`, 등록 요청, `IDeviceMessageHandler`(`R02-R2`).

확인: `Core.Tests`의 토픽 해석(Uplink·Lwt·실패 경우), `rg` JSON·등록 요청 역직렬화 통과.

### 단계 4: Server.Spa 기반 (U4)
- 포트 설정, HTTPS 포트 Redirect, SPA 호스팅.

확인: 정적 파일·HTML fallback·`/health`·Redirect 미들웨어 테스트 통과.

### 단계 5: 장치 REST·FOTA 컨트롤러 (U5)
- 등록·connect·FOTA를 501 ProblemDetails 껍데기로 둔다(등록·connect 구현은 `device-server/T01_01`).

확인: TestServer로 각 경로 501.

### 단계 6: 내장 MQTT 브로커 (U6)
- `MqttPort`·`MqttsPort` 엔드포인트, MQTT 3.1, 토픽 해석·분배, JSON 오류 경고, 로그 핸들러(`R02-R1`~`R02-R5`).

확인: MQTTnet 클라이언트(V310)로 `rg` 발행 → `RegisterAsync` 1회, `msg` 없는 JSON → 핸들러 호출 없음, MQTTS(자체 서명 PFX, TLS 1.2)로도 같은 결과.

### 단계 7: Client (U7)
- React 프로젝트 생성.

확인: `npx tsc -b`, `npm run lint`, `npm test`, `npm run build` 종료 코드 0.

### 단계 8: 통합 검증 (U8)
- 솔루션 빌드·전체 테스트, 배포본 기동과 Ctrl+C 정상 종료.

확인: `dotnet build --no-incremental` 경고 0, `dotnet test --solution` 통과, Ctrl+C 뒤 종료 코드 0과 포트 리슨 없음.
