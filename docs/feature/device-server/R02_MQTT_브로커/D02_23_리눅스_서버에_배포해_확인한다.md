# D02_23 리눅스 서버에 배포해 확인한다

## 상황

암호 목록 제한은 리눅스에서만 동작한다(Windows는 .NET이 `CipherSuitesPolicy`를 지원하지 않아 HTTPS처럼 경고 후 무시). 작업 PC(Windows)의 테스트로는 제한이 실제로 걸리는지 확인할 수 없어, 리눅스에서 확인하는 단계를 넣을지 정해야 했다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C6(`docs/specs/mqtts-tls-policy/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_10`

## 결정

- A. 배포해 확인: 구현 뒤 승인을 받아 리눅스 서버에 실행 파일만 교체하고(설정·DB·인증서 유지), MQTTS에서 목록 밖 암호 거절·장치 암호 수락과 실장비 재접속을 확인한다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 리눅스 테스트만: 배포하지 않고 리눅스 서버 임시 폴더에서 같은 테스트를 돌려 제한만 확인한다. 실장비 확인은 빠진다. | 사용자가 말하지 않음 |
| C. Windows 테스트만: 옵션이 만들어지는지만 확인하고, 리눅스 제한은 확인하지 않음으로 남긴다. | 사용자가 말하지 않음 |

## 경위

- 2026-11-23 옛 작업 `docs/specs/mqtts-tls-policy/decisions.md`(지움. `15dc357`에 있음) D004에서 옮겼다(2026-11-23).

## 코드

- 옛 기록에 코드 위치가 없다. 짝 태스크 `T02_10`의 「고칠 파일」을 본다.
