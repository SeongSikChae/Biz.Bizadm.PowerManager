# D02_01 응답 `sid`는 요청의 `sid`를 그대로 쓴다(없으면 `"0"`)

## 상황

spec 검토 1회차 지적 3. 「무엇을, 왜」는 근거 문서의 응답 예처럼 `"sid":"0"`을 들었는데, 완료 조건 C2는 요청의 `sid`를 그대로 되돌리라고 적어 두 곳이 달랐다. 근거 문서는 응답 `sid` 값을 미확인으로 두고(4절), B540 요청은 고정 문자열 `"sid":"0"`이며, M130-W 요청 `sid`는 2026-11-20 서버 로그에서 `"0"`으로 관찰했다. 어느 쪽이 의도인지 정하지 않으면 구현·테스트 기대값이 갈리고, 실장비가 응답을 받아들이지 않을 때 원인 후보를 좁히는 근거가 남지 않는다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 「무엇을, 왜」 응답 형식 항목, C2(`docs/specs/tisyn-response/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_05`

## 결정

- A. 요청 `sid` 되돌림: 응답 `sid`에 요청의 `sid` 문자열을 그대로 쓰고, 요청에 `sid`가 없으면 `"0"`을 쓴다. 「무엇을, 왜」를 이에 맞추고 이유를 적는다.

## 이유

- 요청과 응답의 짝을 맞추는 일반적인 방식이고, 지금 관찰한 요청 `sid`가 `"0"`이라 실장비에서는 근거 문서의 예와 같은 값이 된다. B는 지금 장비에서는 결과가 같지만, 장치가 `"0"`이 아닌 `sid`를 보내는 경우 요청과 응답의 짝이 어긋나고, 그렇게 고정할 근거(수신 파서 확인)도 없다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 항상 `"0"`: 근거 문서의 응답 예대로 요청과 상관없이 응답 `sid`를 늘 `"0"`으로 둔다. C2를 이에 맞춘다. | 위 「이유」에 함께 적힘 |
