# D02_30 TLS 1.0·1.1 openssl 확인 이력의 출처를 밝힌다

## 상황

plan 검토 4회차 지적 1(회귀). 검토 의견: `D02_29`(옛 D010)에서 `-tls1` 옵션을 앞에 더하면서 plan 오류·위험 넷째 항목 끝 괄호 "같은 서버에서 이 옵션으로 `alert protocol version`을 받은 적 있음"이 TLS 1.0에도 걸리게 됐는데, 변경 문서·회차 사본 어디에도 `-tls1`로 확인한 기록이 없다. 왜 문제인지: 출처 없는 주장이 확인된 것처럼 읽힌다(실제로는 2026-11-23 리눅스 서버 18443·8883에서 `-tls1`·`-tls1_1`을 `-cipher "AES128-SHA:@SECLEVEL=0"`로 돌려 `alert protocol version`을 받았으나 문서에 적지 않았음).

- 정한 단계: plan
- 관련: 옛 작업 스펙의 plan.md 오류·위험 넷째 항목, 작업 문서 배경(`docs/specs/mqtts-tls-policy/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_10`

## 결정

- A. 출처를 밝혀 고침: 괄호를 포트·옵션·결과와 "작업 문서 배경에 기록"으로 바꾸고 작업 문서 배경에 결과를 적는다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. TLS 1.1에만 걸치게 좁힘: 괄호를 `-tls1_1` 옵션에만 걸리게 한다. | 사용자가 말하지 않음 |

## 경위

- 2026-11-23 옛 작업 `docs/specs/mqtts-tls-policy/decisions.md`(지움. `15dc357`에 있음) D011에서 옮겼다(2026-11-23).

## 코드

- 옛 기록에 코드 위치가 없다. 짝 태스크 `T02_10`의 「고칠 파일」을 본다.
