# D02_24 목록에 TLS 1.3 암호가 없을 때 MQTTS는 경고를 남기지 않는다

## 상황

spec 검토 1회차 지적 2. 검토 의견: C3·C4에는 잘못된 이름 경고와 Windows 경고만 있고, HTTPS의 `CreateCipherSuitesPolicy`가 목록에 TLS 1.3 암호가 없을 때 내는 HTTP/3 실패 경고를 MQTTS가 내는지가 없다. 같은 함수를 다시 쓰면 HTTP/3 문구의 경고가 한 번 더 남는다. 왜 문제인지: 완료 조건으로 맞는 동작을 판정할 수 없다. MQTTS는 TLS 1.3 암호가 없어도 TLS 1.2로 연결되므로 실패로 이어지지 않는다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C3(`docs/specs/mqtts-tls-policy/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_10`

## 결정

- A. MQTTS는 경고 안 냄: C3에 "목록에 TLS 1.3 암호가 없을 때의 HTTP/3 경고는 MQTTS 때문에 다시 남기지 않는다"를 붙인다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. MQTTS 전용 경고: 목록에 TLS 1.3 암호가 없으면 MQTTS는 TLS 1.3 연결을 받지 않는다는 경고를 따로 남긴다. | 사용자가 말하지 않음 |
