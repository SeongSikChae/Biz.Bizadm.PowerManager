# D02_08 재분석 결과의 근거 문서 반영을 후속 작업으로 둔다

## 상황

`D02_07`(옛 D003) 대체. spec 검토 3회차 지적 1. 검토 의견: `D02_07`(옛 D003)으로 spec이 B540 재분석 결과(접속 직후 QoS 0 구독, 토픽 무검사, 응답 형식 `n`·`sv`)와 M130-W 2.01.58 분석 결과를 "#21의 근거 문서 반영 작업(T011)에서 적는다"고 했지만, `docs/specs/tisyn-response/tasks.md`(지움. `15dc357`에 있음)의 T011은 T010의 실장비 판정 결과를 근거 문서 4절 시간 동기 미확인 항목(응답 값 키·`sid`, 동기 뒤 재송신 여부)과 5절 M130-W 관찰에 적는 작업이다. 그래서 QoS 0 구독·토픽 무검사·M130-W 펌웨어 분석은 어느 작업에도 들어 있지 않고, spec이 지켜지지 않을 약속을 하며 근거 문서의 "QoS 미확인"이 계속 남을 수 있다. `D02_07`(옛 D003) 이유의 "근거 문서 반영이 원래 #21의 작업(T011)"도 T011 문구와 맞지 않는다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 무엇을·왜(`docs/specs/mqtt-subscribe-log/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_06`

## 결정

- A. 후속 작업으로 둔다: spec 문구를 "이 작업에서도 근거 문서에 반영하지 않으며, 반영은 따로 할 후속 작업으로 둔다"로 바꾸고, 후속 작업(근거 문서에 B540 재분석·M130-W 분석 반영)을 작업 기록에 남긴다.

## 이유

- A를 고른 이유는 이 작업(로그 추가)의 범위를 지키면서 문서의 약속을 사실과 맞추기 때문이다. 근거 문서 반영은 #21을 마무리할 때 실장비 판정과 함께 하기 좋다. B는 이 작업의 범위와 검토 대상을 키우고, `D02_07`(옛 D003)에서도 같은 이유로 고르지 않았다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
