# D02_03 기준 spec R5에는 발행 실패 처리를 적지 않고, tasks T007에서 그 항목을 뺀다

## 상황

tasks 검토 1회차 지적 1. T007은 기준 spec R5를 spec 「기준 spec mqtt-broker에 미치는 변경」대로 고친다고 하면서 괄호 안에 그 절에 없는 "발행 실패는 Error 로그만"을 넣었다. 그 절이 R5에 직접 담기로 한 것은 받은 내용의 Information 로그 유지, 중계 꺼짐이면 retain 없이 `w` `/99/0/1` 전송(요청 `sid`, 없으면 `"0"`, UTC epoch 초 문자열), 응답 로그, 중계 켜짐이면 응답 안 함, 명령 발행 `w`·`chg`·`reb`는 `NotImplementedException`의 다섯 가지이고, 발행 실패 처리는 완료 조건 C4에만 있다. T007대로 고치면 기준 spec R5가 spec이 정한 내용과 달라져 T007 체크포인트와 구현 후 검토(C5)에서 판정이 갈린다.

- 정한 단계: tasks
- 관련: 옛 작업 스펙의 tasks.md T007(`docs/specs/tisyn-response/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_05`

## 결정

- A. T007에서 빼기: tasks.md T007 괄호 안의 `, 발행 실패는 Error 로그만`을 지운다. spec.md·plan.md는 그대로 두고, 실패 처리 동작은 C4와 T004 구현·T005 실패 경로 단위 테스트로 그대로 확인한다.

## 이유

- spec이 정한 R5 범위에 tasks를 맞추고 확인받은 문서를 건드리지 않는다. 실패 처리는 C4와 테스트로 확인되므로 동작이 빠지지 않는다. B는 기준 spec이 조금 더 자세해지는 대신 검토와 확인을 세 단계 다시 해야 해 얻는 것에 비해 비용이 크다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
