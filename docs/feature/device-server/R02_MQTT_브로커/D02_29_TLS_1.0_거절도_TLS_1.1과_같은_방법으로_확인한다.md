# D02_29 TLS 1.0 거절도 TLS 1.1과 같은 방법으로 확인한다

## 상황

tasks 검토 1회차 지적 1. 검토 의견: spec C1은 "TLS 1.0·1.1 핸드셰이크는 거절한다"인데 plan 검증 전략 C1·요약과 tasks T005·T009는 TLS 1.1만 확인한다. 왜 문제인지: C1이 통과로 적혀도 TLS 1.0 거절은 확인되지 않은 채 남는다.

- 정한 단계: tasks
- 관련: 옛 작업 스펙의 plan.md 요약·오류·위험·검증 전략 C1·C6, tasks.md T005·T009(`docs/specs/mqtts-tls-policy/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_10`

## 결정

- A. plan·tasks에 TLS 1.0 추가: plan 요약·오류·위험(TLS 1.1 항목)·검증 전략 C1·C6과 tasks T005·T009에 TLS 1.0을 더한다. 작업 PC 테스트는 "TLS 1.0·1.1이 성공하지 않음", 리눅스는 `openssl s_client -tls1 -cipher 'AES128-SHA:@SECLEVEL=0'`이 서버 경고로 실패하는지(클라이언트 쪽 실패면 판정 못함). 확정된 plan의 의도 변경이라 plan 검토·확인을 다시 받는다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
