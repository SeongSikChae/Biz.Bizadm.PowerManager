# D02_09 C1 테스트는 필터를 QoS가 높은 순서로 보내 필터마다 승인 결과를 단언한다

## 상황

plan 검토 2회차 지적 1. 검토 의견: plan 검증 전략 C1은 한 SUBSCRIBE에 QoS 0·1 필터를 보내고 필터마다 요청 QoS대로 승인(`GrantedQoS0`·`GrantedQoS1`)되는지 확인한다고 했다. 그런데 MQTTnet 5.2 서버는 필터를 QoS 내림차순으로 처리하며 SUBACK 결과 코드를 그 순서로 담고(디컴파일 `MqttClientSubscriptionsManager.Subscribe`의 `OrderByDescending`), 클라이언트는 결과 코드를 요청 필터 순번대로 짝짓는다(`MqttClientSubscribeResultFactory`). 그래서 QoS 0, 1 순서로 요청하면 결과가 뒤바뀌어 보인다. 이번 변경과 무관한 기존 동작이라, 적힌 대로 테스트하면 변경과 관계없이 C1 테스트가 실패해 C7을 채우지 못한다.

- 정한 단계: plan
- 관련: 옛 작업 스펙의 plan.md 검증 전략 C1(`docs/specs/mqtt-subscribe-log/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_06`

## 결정

- A. QoS가 높은 순서로 요청: 필터를 QoS 1, QoS 0 순서로 보내 순번과 처리 순서를 맞추고, 필터마다 결과 코드를 단언한다. 로그 순서는 단언하지 않는다.

## 이유

- A를 고른 이유는 필터마다 요청 QoS대로 승인됨을 정확히 확인하면서 기존 순서 동작에 걸리지 않기 때문이다. B는 필터와 결과가 뒤바뀌어도 통과해 "필터마다 요청 QoS대로 승인"을 확인하지 못해 고르지 않았다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
