# D02_19 catch 주석 수정은 tasks.md T004에만 더한다

## 상황

tasks 검토 1회차 지적 2. 검토 의견: `MqttBrokerHostedService.cs`의 catch 주석 "관찰 로그 실패로 접속을 막지 않는다."는 C4(예외 때 거부) 뒤 정반대 뜻이 되는데, plan.md와 T004는 클래스·메서드 주석 두 곳만 고친다고 적었다. 작업 목록대로만 하면 반대 뜻 주석이 남으므로 문제다.

- 정한 단계: tasks
- 관련: 옛 작업 스펙의 tasks.md T004(`docs/specs/mqtt-connect-auth/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_09`

## 결정

- A. T004에 추가: T004 문구에 catch 주석 수정을 더한다. plan.md는 바꾸지 않는다.

## 이유

- A는 tasks 한 줄로 끝나고, 주석 수정은 설계 변경이 아니라 plan을 다시 확인받을 필요가 없다. B는 주석 한 줄에 비해 절차 비용이 커 고르지 않았다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안
