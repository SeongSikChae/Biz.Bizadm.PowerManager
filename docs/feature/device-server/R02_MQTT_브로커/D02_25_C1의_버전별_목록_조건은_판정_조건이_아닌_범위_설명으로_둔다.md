# D02_25 C1의 버전별 목록 조건은 판정 조건이 아닌 범위 설명으로 둔다

## 상황

spec 검토 2회차 지적 1(회귀). 검토 의견: 1회차에 C1에 덧붙인 "암호 목록이 적용될 때(C2)는 목록에 그 버전의 암호가 있을 때만 그 버전으로 연결된다"가 "목록에 그 버전 암호가 없으면 거절"이라는 새 조건을 만드는데, Windows에서는 목록이 무시되고(C4) 리눅스 확인은 C6 배포 확인뿐이며 그 서버 목록에는 TLS 1.2·1.3 암호가 모두 있어 거절 경우가 나오지 않는다. 왜 문제인지: 완료 판정을 할 수 없다. 서버 목록의 TLS 1.3 암호 4종이 OpenSSL 기본 TLS 1.3 암호 3종을 모두 포함해, 설정을 그대로 두면 TLS 1.3 제한이 걸리는지도 가릴 수 없다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C1(`docs/specs/mqtts-tls-policy/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_10`

## 결정

- A. 범위 설명으로 바꿈: C1 끝 문장을 "C1의 TLS 1.3 수락은 암호 목록이 적용될 때(C2) 목록에 TLS 1.3 암호가 있는 경우를 말한다"로 바꾼다. TLS 1.3에도 목록이 걸리는지는 TLS 1.2에서 확인하는 것(C2·C6)과 같은 .NET 정책에 기댄다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 리눅스 임시 서버로 확인: C6에 리눅스 서버 임시 폴더에서 TLS 1.3 암호를 뺀 목록으로 다른 포트에 서버를 띄워 TLS 1.3 거절·TLS 1.2 연결을 확인하는 단계를 넣고, D004를 넓힌다. | 사용자가 말하지 않음 |
