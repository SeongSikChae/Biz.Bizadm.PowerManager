## 할 일

### 단계 1: 브로커 로그
- 두 로그 항목에 ClientId·원본 페이로드(UTF-8, 이스케이프 없음)를 넣고 4096바이트에서 자른다. 분배 경로는 바꾸지 않는다.

### 단계 2: 테스트
- 알 수 없는 오퍼레이션, 원시 TCP MQTT 3.1 CONNECT의 `/lwt` Will, 5000바이트 페이로드.

확인: 새 테스트 3개와 전체 테스트 통과. 기준점 대비 diff에서 분배 메서드 호출 줄과 `TryDeserialize`가 바뀌지 않음.

### 단계 3: 옛 기준 spec
- `mqtt-broker` 기준 spec을 새로 쓴다.

## 위험

- UTF-8이 아닌 바이트는 대체 문자로 디코딩되고, 4096바이트 경계에서 여러 바이트 문자가 잘리면 끝이 대체 문자가 된다.
- 해석 불가 토픽 로그가 서버 → 장치 명령 토픽에도 남아 로그 양이 늘 수 있다(4096바이트 상한).
