# D02_12 C1의 판정 문구를 원시 TLS 레코드 개수로 바꾼다

## 상황

의도 변경(spec 확인 뒤, plan 작성 전 실험에서 발견). 확인받은 C1 괄호 "(TLS 스트림을 한 번 읽어 PUBLISH 패킷 전체를 얻는다)"는 판정 방법으로 맞지 않다. 실험(MQTTnet.Server 5.2.0.1603 TLS 1.2, 117바이트 PUBLISH)에서 분할이 켜져 있어도 `SslStream`이 이미 도착한 두 레코드를 합쳐 돌려주어 한 번 읽기로 전체를 얻는 경우가 섞여 나왔다(주입 전에 건 읽기 3회 중 50/117/117바이트, 300ms 뒤 읽기는 늘 117바이트). 반면 `SslStream` 아래의 원시 수신 바이트에서 TLS 레코드 머리를 세면 분할 켬 2개(74·91바이트), 끔 1개(141바이트)로 3회 모두 같았다. C1 본문("TLS 레코드 하나로 받는다")은 맞다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C1(`docs/specs/mqtt-no-fragmentation/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_07`

## 결정

- A. 괄호를 레코드 머리로 바꿈: 괄호를 "(클라이언트가 받은 원시 바이트에서 그 PUBLISH를 담은 TLS 레코드가 하나다)"로 바꾸고 spec 검토·확인을 다시 한다.

## 이유

- A는 완료 조건의 판정 방법이 실제로 결정적인 방법과 같아지고, 분할을 다시 켜면 테스트가 반드시 실패한다. B는 본문만으로도 확인할 수 있지만 "레코드 하나"를 무엇으로 보는지가 spec에서 덜 분명하다. 고치지 않으면 확인받은 문서에 맞지 않는 판정 방법이 남아 plan·구현 후 검토에서 어긋남이 생긴다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
