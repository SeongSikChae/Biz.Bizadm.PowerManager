# D02_22 인증서 체인은 이번 범위에서 뺀다

## 상황

`D02_21`(옛 D002) 대체. 확인해 보니 리눅스 서버의 MQTTS는 이미 HTTPS와 같은 체인(`iot.bizadm.biz` ← `AzureLeaf`)을 보낸다(`openssl s_client -showcerts`로 8883·18443 확인). `AzureLeaf`·`AzureRoot`가 OS 신뢰 저장소(`/etc/pki/ca-trust/source/anchors/`)에 있어 .NET이 그곳에서 체인을 만들기 때문이다. MQTTnet 5.2 TLS 엔드포인트 옵션에는 서버 인증서 제공자(`CertificateProvider`)만 있고 체인을 넘기는 항목이 없어(리플렉션으로 `MqttServerTlsTcpEndpointOptions` 속성 확인), 설정의 `CertificateChain`으로 체인을 보내려면 MQTT 호스팅 구조를 바꿔야 한다(방법 미확인).

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 「범위 밖」(`docs/specs/mqtts-tls-policy/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_10`

## 결정

- A. 이번엔 빼기: TLS 버전과 암호 목록만 다루고, 체인이 OS 저장소에 기대는 점은 스펙에 기록한다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 설정으로 보내기: OS 저장소와 상관없이 `CertificateChain`으로 MQTTS에도 체인을 보낸다. 호스팅 구조 변경과 설계 조사가 더 필요하다. | 사용자가 말하지 않음 |

## 경위

- 2026-11-23 옛 작업 `docs/specs/mqtts-tls-policy/decisions.md`(지움. `15dc357`에 있음) D003에서 옮겼다(2026-11-23).
- 앞 결정 `D02_21`(옛 D002)을 대신한다.

## 코드

- 옛 기록에 코드 위치가 없다. 짝 태스크 `T02_10`의 「고칠 파일」을 본다.
