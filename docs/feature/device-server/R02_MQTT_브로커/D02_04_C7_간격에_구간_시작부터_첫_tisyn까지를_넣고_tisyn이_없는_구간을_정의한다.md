# D02_04 C7 간격에 구간 시작부터 첫 `tisyn`까지를 넣고, `tisyn`이 없는 구간을 정의한다

## 상황

의도 변경(구현 후 검토 1회차 지적 1). C7은 판정 구간을 장비의 첫 응답 로그 시각부터 60분으로 두고 간격을 "구간 안의 이웃한 두 `tisyn` 사이와 마지막 `tisyn`부터 구간 끝까지"로만 정했다. 서버는 요청 로그(`Device message "tisyn"`)를 남긴 뒤 응답 로그(`Time sync response sent`)를 남기므로 첫 요청은 늘 구간 밖이다. 2026-11-21 관찰에서 구간 안 `tisyn`은 약 3600초 뒤의 하나뿐이었고, 정의된 간격은 그로부터 구간 끝까지 0.04~0.08초뿐이라 문구대로면 "동기 안 됨"이 된다. 실제로는 약 3600초 동안 재요청이 없어 동기된 것이므로, 구간 정의에 빈틈(구간 시작부터 첫 `tisyn`까지, `tisyn`이 없는 구간)이 있다.

- 정한 단계: 구현
- 관련: 옛 작업 스펙의 spec.md C7, 작업 문서 T010 판정, 근거 문서 5절(`docs/specs/tisyn-response/`(지움. `15dc357`에 있음)), 짝 태스크 `T02_05`

## 결정

- A. C7 간격 정의 보완: 간격에 "구간 시작(첫 응답 로그 시각)부터 구간 안 첫 `tisyn`까지"를 더하고, 구간 안에 `tisyn`이 없으면 구간 전체(60분)를 간격 하나로 본다. 의도 변경으로 spec 검토·확인부터 다시 한다.

## 이유

- A는 실제 동작과 맞는 판정이 규칙대로 성립하고 `tisyn`이 없는 구간도 정의된다. B는 실제와 반대인 판정이 기록으로 남고 정의의 빈틈도 그대로다. 고치지 않으면 기록이 spec 규칙과 로그 순서에 맞지 않는다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
