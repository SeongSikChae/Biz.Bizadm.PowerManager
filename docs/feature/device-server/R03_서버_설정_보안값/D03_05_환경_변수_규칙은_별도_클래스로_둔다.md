# D03_05 환경 변수 규칙은 별도 클래스로 둔다

## 상황

plan 검토 1회차 지적 3. 검토 의견은 plan.md 「결정」의 "`KmsSecretProtector` 안의 메서드 — 시험하려면 실제 저장소가 필요"가 사실과 다르다는 것이다. `InternalsVisibleTo`가 있어 내부 메서드도 저장소 없이 시험할 수 있으므로 근거만 틀린 채 남는다. 이유를 고칠 것인가, 메서드로 옮길 것인가.

- 정한 단계: plan
- 관련: 옛 작업 스펙의 plan.md 결정(`docs/specs/credential-store/`(지움. `15dc357`에 있음)), 짝 태스크 `T03_01`

## 결정

- A. 이유 고침: 클래스를 두고 이유를 "환경 변수 규칙을 저장소·DEK 처리와 나눠 읽고 시험하기 쉽게 한다"로, 대안의 이유를 "동작은 같지만 `Protect`와 한 파일에 섞인다"로 바꾼다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 메서드로 옮김: 새 파일을 없애고 `KmsSecretProtector`의 내부 메서드로 둔다. | 사용자가 말하지 않음 |
| C. 고치지 않음: 이유를 그대로 둔다. | 사용자가 말하지 않음 |
