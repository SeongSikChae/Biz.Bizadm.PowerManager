# D01_08 상태 보고는 B540 관찰 출처를 적고, 정해진 rg·tisyn 뒤 바로 한 번 보낸 뒤 주기마다 보낸다

## 상황

spec 검토 1회차 지적 6. (가) `n`·`notify/json`·`ti` `""` 관찰은 근거 문서 5절의 M130-W 관찰이고 3절은 B540 보고를 미확인으로 두는데, spec은 기본 모델 B540에서 관찰로 들었다(실제로는 2026-11-19 서버 로그에서 B540도 같은 형식으로 보냈지만 출처가 없었다). (나) "접속 뒤 주기마다"의 첫 송신 시점이 모호해 테스트 기대값을 정할 수 없었다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 무엇을·왜, C6(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 출처 + 즉시 첫 송신: B540 관찰 출처를 더하고, 주기가 0보다 크면 정해진 `rg`·`tisyn` 뒤 바로 한 번 보내고 그 뒤 주기마다 보낸다.

## 이유

- 실장비도 접속 직후(`rg` 뒤 1~2초 안) 보고를 보냈다. B는 실장비와 달라 다원이 장치를 온라인으로 보는 시점이 늦어질 수 있다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 출처 + 한 주기 뒤: 출처는 같고, 첫 송신은 구독 결과를 받은 때부터 한 주기 뒤로 한다. | 위 「이유」에 함께 적힘 |
