# D01_17 URL 후보가 없는 FOTA 메시지는 C14에서 요청하지 않고, C13에서 이을 수 있으면 C15로 받아 결과까지 적는다

## 상황

`D01_15`(옛 D015) 보완. spec 검토 5회차 지적 2. C13은 "URL을 받음"과 "FOTA 메시지 없음"만 다뤄, FOTA로 보이는 메시지는 왔지만 URL이 없는(주소·포트·경로가 나뉜) 경우의 완료 기준이 없었다. 또 C14의 "기록을 보고 C15로 받는다"는 사람이 할 일이라 C12 자동 테스트로 확인할 수 없었다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C13, C14(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 이을 수 있으면 C15로: C14에는 "URL 후보가 없으면 FOTA 요청을 보내지 않는다(원문은 C8대로 기록)"만 남기고, C13에 "받은 메시지를 적고, 다원이 보낸 값으로 URL을 이을 수 있으면 C15로 받아 결과까지 적는다. 이을 수 없으면 메시지만 적으면 완료"를 더한다.

## 이유

- 이을 수 있는 값이 있는데 받지 않으면 FOTA를 넣은 목적을 놓친다. B는 단순하지만 이을 수 있는 값이 있어도 받지 않고 끝낼 수 있다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
