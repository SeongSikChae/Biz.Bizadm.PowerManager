# D01_03 접속 뒤에는 정해진 발행과 콘솔 입력 발행만 하고 자동 응답은 하지 않는다

## 상황

다원 브로커에 접속한 뒤 가짜 장비가 무엇을 보내고, 받은 메시지에 응답할지 정해야 했다. 보내고 받은 원문은 모든 선택지에서 기록한다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C6, C7, C8, 범위 밖(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 정해진 발행 + 콘솔 입력: 접속 직후 `rg`·`tisyn`을 보내고, 주기적으로 `tisyn`·상태 보고(`n`)를 보낸다(내용·주기는 설정). 실행 중 콘솔에 토픽·페이로드를 입력해 임의 메시지를 보낼 수 있다. 자동 응답은 하지 않는다.

## 이유

- 받은 메시지를 보고 바로 다른 메시지를 시험할 수 있어 형식을 찾는 데 맞다. B는 단순하지만 시험할 때마다 다시 실행해야 한다. C는 앱에 온라인으로 보일 가능성은 있지만 응답 형식 자체가 미확인이라 추측으로 만든 응답이 기록을 흐릴 수 있다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

| C. 간단한 자동 응답까지: A에 더해 다원이 보낸 `w`·`r`에 고정 형식으로 응답한다. | 위 「이유」에 함께 적힘 |
