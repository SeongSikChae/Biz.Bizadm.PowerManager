# D01_01 가짜 장비 클라이언트를 새 콘솔 프로젝트로 만든다

## 상황

다원 서버에 장치처럼 접속하는 가짜 장비 클라이언트를 어떤 형태의 프로그램으로 만들지 정해야 했다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 무엇을·왜, C1(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 새 콘솔 프로젝트: `src`에 독립 콘솔 프로젝트를 두고 설정 파일을 읽어 실행한다. Core의 `DeviceVerify`·`DeviceTopic`·`MqttEnvelope`를 그대로 쓴다.

## 이유

- 장치 설정 도구와 목적(장치 설정 vs 다원 서버 통신 관찰)이 달라 섞지 않는 편이 낫고, Core의 계산·토픽 코드를 그대로 쓸 수 있다. B는 따로 배포할 것이 없다는 장점이 있지만 Wi‑Fi·TCP 설정 도구에 MQTT 클라이언트가 섞인다. C는 대화형 분석에는 편하지만 장시간 접속 유지와 상태 관리가 복잡하다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. DeviceConfig CLI 하위 명령: 기존 장치 설정 CLI(Wi‑Fi·TCP 설정 도구)에 명령을 더한다. | 위 「이유」에 함께 적힘 |
| C. MCP 도구: 에이전트가 접속·발행·수신 조회를 도구로 부르게 한다. | 위 「이유」에 함께 적힘 |
