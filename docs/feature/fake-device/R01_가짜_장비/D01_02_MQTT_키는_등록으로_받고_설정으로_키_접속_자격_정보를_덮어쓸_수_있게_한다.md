# D01_02 MQTT 키는 등록으로 받고, 설정으로 키·접속 자격 정보를 덮어쓸 수 있게 한다

## 상황

다원 브로커 접속에 쓸 `mqtt_key`와 ClientId·사용자명·비밀번호를 어떻게 정할지 정해야 했다. 이미 다원 계정에 등록된 mac은 등록 요청이 409 `REGISTERED`로 거절되어 새 키를 받을 수 없다(2026-11-20 중계 기록).

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C1, C2(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 등록 + 설정으로 덮어쓰기: 기본은 `register/create`로 다원 키를 받아 비밀번호로 쓴다. 설정에 `mqtt_key`를 주면 등록을 건너뛰고, ClientId·사용자명·비밀번호도 설정으로 바꿀 수 있다.

## 이유

- 이미 등록된 mac이나 다른 경로로 구한 키로도 접속을 시험할 수 있고, 접속 규칙 추정이 틀려도 코드를 고치지 않고 여러 조합을 시험할 수 있다. B는 단순하지만 409로 막히거나 추정이 틀리면 코드를 고쳐야 한다. C는 키를 늘 다른 방법으로 구해야 해 등록 응답 자체를 관찰할 수 없다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 등록으로만: 항상 `register/create`로 키를 받고 정해진 규칙으로만 접속한다. | 위 「이유」에 함께 적힘 |
| C. 설정으로만: 등록 요청 없이 설정 값으로만 접속한다. | 위 「이유」에 함께 적힘 |
