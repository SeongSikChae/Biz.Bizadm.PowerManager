# D01_23 실패 경로 세 가지(C3 연결 실패, C4 접속 시간 초과, C16 FOTA 연결 실패)의 테스트를 plan과 tasks에 함께 더한다

## 상황

tasks 검토 1회차 지적 1. spec C3의 `device/connect` 연결 실패, C4의 MQTT 접속 10초 시간 초과, C16의 FOTA 연결 실패가 plan 검증 전략에도 tasks에도 없었다. spec C12는 이 조건들의 자동 테스트를 요구한다. 빠진 곳이 이미 확인받은 plan의 검증 전략 표라, plan을 고치면 의도 변경이 되어 plan 검토·확인을 다시 해야 한다.

- 정한 단계: tasks
- 관련: 옛 작업 스펙의 plan.md 바꿀 파일·구조(가짜 브로커), 검증 전략 C3·C4·C16, tasks.md T016·T019·T023·T026(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. plan·tasks 둘 다: plan 검증 전략 C3·C4·C16 행과 T016(CONNACK 지연 설정)·T019·T023·T026에 세 경우를 더하고, plan 검토 다음 회차·plan 확인·tasks 검토를 다시 한다.

## 이유

- plan과 tasks가 어긋나지 않고, spec C12가 요구하는 확인이 갖춰진다. B는 plan을 다시 확인받지 않아 빠르지만 plan과 tasks가 어긋난 채 남아, 다음 tasks 검토가 같은 어긋남을 다시 찾는다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
