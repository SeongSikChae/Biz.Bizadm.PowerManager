# D01_22 C8 "응답하지 않음"은 수신 기록이 생긴 뒤 1초 동안 클라이언트 발행이 없는지로 본다

## 상황

plan 검토 1회차 지적 2. plan은 C8 검증에서 "QoS 1 발행으로 순서를 맞춤"이라고 했다. 하지만 spec C5가 구독을 QoS 0으로 정해, 브로커가 QoS 1로 넣어도 QoS 0으로 전달되고 클라이언트가 PUBACK을 보내지 않는다. 그래서 "처리한 뒤 발행이 없다"는 확인이 처리 전에 끝나 늘 통과할 수 있었다.

- 정한 단계: plan
- 관련: 옛 작업 스펙의 plan.md 검증 전략 C8(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 기록 뒤 1초 관찰: 수신 기록(`publish` `dawon-to-device`)이 생길 때까지 기다린 뒤 1초 동안 클라이언트가 정해진 발행 밖의 메시지를 보내지 않는지 본다.

## 이유

- 단순하고, 응답을 보낸다면 수신 처리 바로 뒤일 것이라 1초면 충분하다. B는 콘솔 명령과 수신 처리가 따로 돌아 표식이 순서를 보장하지 못한다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
