# D01_25 생략한 ContentRootPath는 설정 모델을 바꾸지 않고 따로 정한 기준 경로로만 쓴다

## 상황

tasks 검토 2회차 지적 1. 앞 회차 수정으로 T007 1단계가 빈 `ContentRootPath`를 실행 폴더로 채우게 됐다. 그런데 2단계는 `Rewrite`이면 `DeviceConfig.App`처럼 설정 모델 전체를 설정 파일에 다시 쓴다. 그래서 비밀 값을 처음 암호화하는 실행에서 실행 폴더 절대 경로가 설정 파일에 굳고, 실행 폴더를 옮기면 DEK 파일·기록 폴더가 처음 폴더를 계속 가리키게 됐다.

- 정한 단계: tasks
- 관련: 옛 작업 스펙의 tasks.md T006, T007, T009(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 기준 경로 따로: 설정 모델의 `ContentRootPath`는 바꾸지 않고, 정한 기준 경로를 KMS DEK 경로·Host·기록 폴더에 따로 넘긴다. T009에 다시 쓴 뒤에도 설정 파일의 `ContentRootPath`가 비어 있는지 확인을 더한다.

## 이유

- 모델과 실행 값을 나누면 되돌리기를 잊을 일이 없다. B는 다시 쓰는 곳이 늘면 또 새는 구조다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
