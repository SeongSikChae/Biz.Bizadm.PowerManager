# R01 가짜 장비

## 목적

개발자가 다원이 장치에 보내는 메시지의 실제 형식을 실장비 없이 관찰하려 한다. 가짜 장비(`Biz.Bizadm.PowerManager.FakeDevice.App`)는 B540을 흉내 내어 다원 REST 서버(`dwapi.dawonai.com:18443`)에 등록하고, 다원 브로커(`dwmqtt.dawonai.com:8883`)에 장치와 같은 방식(MQTT 3.1, TLS 1.2)으로 접속한다. 정해진 장치 메시지와 콘솔에서 입력한 메시지를 보내고, 받은 메시지에는 응답하지 않으며, FOTA URL이 오면 이미지를 받아 파일로만 저장하고, 보내고 받은 원문을 JSONL로 기록한다.

| `R01-R2` | 설정에 `mqtt_key`가 없으면 프로그램은 다원 REST 서버에 HTTPS `POST /api/v1/devices/register/create`를 헤더 `Content-Type: application/json`, `X-HIT-Version: 1.0`, 본문 `{"account":{"user_id":…},"device":{"mac":…,"model_id":…,"company":…,"lati":…,"long":…,"verify":"true"}}`(`docs/reference/b540-rest-api.md` 2절 첫 형식, 값은 설정)로 보낸다. 성공 조건은 200, 본문이 JSON 객체, 최상위 `mqtt_key`가 비어 있지 않은 문자열이다. 성공하면 그 `mqtt_key`를 이번 실행의 키로 쓴다. 최상위 `verify`가 문자열이면 `device-server/R01-R3` 계산식(설정의 `verify` 확인 서버 주소, mac, 키)으로 계산한 값과 같은지 판정해 기록과 콘솔에 남기고, 같지 않아도 계속한다. 키에 치환표 밖 문자가 있으면 판정을 "계산 불가"로 기록·콘솔에 남기고 계속한다. 성공 조건을 채우지 못하거나, 연결에 실패하거나, 10초 안에 응답이 없으면 그 결과를 기록하고 콘솔에 상태 코드(또는 오류)를 쓴 뒤, MQTT에 접속하지 않고 0이 아닌 종료 코드로 끝난다. | 반영 | |
| `R01-R3` | 키가 정해지면(등록 성공 또는 설정) 프로그램은 `GET /api/v1/device/connect/{회사}-{모델}-{mac}`을 보내고 응답을 기록한다. 응답 내용, 연결 실패, 10초 시간 초과와 관계없이 MQTT 접속으로 넘어간다. | 반영 | |
| `R01-R4` | 프로그램은 MQTT 3.1(`MQIsdp`)로 다원 브로커에 TLS 1.2로 접속한다. `R01-R1`의 ClientId·사용자명·비밀번호·keepalive·Will을 쓰고, clean session을 켠다. 다원이 거부하면 CONNACK 반환 코드를 기록하고 콘솔에 쓴 뒤 0이 아닌 종료 코드로 끝난다. 연결 실패, 10초 시간 초과도 같은 방식으로 끝난다. | 반영 | |
| `R01-R5` | 접속하면 프로그램은 `{접두}.v1/iot-server/{회사}-{모델}-{mac}/#`를 QoS 0으로 구독하고, 구독 요청과 SUBACK 결과를 기록한다. 10초 안에 SUBACK이 없으면 기록하고 0이 아닌 종료 코드로 끝난다. SUBACK이 실패 값이면 기록하고 콘솔에 쓴 뒤 `R01-R6`으로 넘어간다. | 반영 | |
| `R01-R6` | 구독 결과를 받으면 프로그램은 정해진 메시지를 보낸다. 모든 발행 토픽은 `{접두}.v1/{회사}-{모델}-{mac}/iot-server/{접미}`이고, QoS는 설정값, retain은 없음이다. `rg`(설정이 켜져 있으면 접속 직후 한 번): 접미 설정값, 페이로드 `{"sid":"0","msg":{"o":"rg","e":[…]}}`, 요소 `/3/0/0`=회사, `/3/0/1`=모델, `/3/0/2`=mac, `/3/0/3`=펌웨어 버전, `/3/0/997`=`1`, `/3/0/998`=`1.0`, `/3/0/999`=`1`(각각 `{"n":…,"sv":…}`). `tisyn`: 설정이 켜져 있으면 `rg` 뒤에 한 번, 주기가 0보다 크면 그 뒤로 주기마다 보낸다. 접미 `timesync/json`, 페이로드 `{"sid":"0","msg":{"o":"tisyn","e":[]}}`. 상태 보고: 주기가 0보다 크면 정해진 `rg`·`tisyn` 뒤 바로 한 번, 그 뒤 주기마다 보낸다. 접미 `notify/json`, 페이로드 `{"sid":"1","msg":{"o":"n","e":[…]}}`, 요소는 설정의 요소 목록을 순서대로 `{"n":…,"sv":…,"ti":""}`로 넣는다. | 반영 | |
| `R01-R7` | 실행 중 콘솔에서 한 줄 명령을 받으면 프로그램은 다음처럼 처리한다. 토픽과 페이로드를 받아 그대로 발행한다(QoS는 설정값, retain 없음. 장치 발행 접두 `{접두}.v1/{장치 키}/iot-server/`를 줄여 접미만 쓰는 방법도 있고, 페이로드는 JSON인지 따지지 않는다). FOTA 명령은 `R01-R15`·`R01-R16`대로 처리한다. 종료 명령을 받으면 `R01-R11`대로 끝낸다. 알 수 없는 명령은 사용법을 콘솔에 쓰고 무시한다. | 반영 | |
| `R01-R8` | 다원에서 메시지를 받으면 프로그램은 토픽·QoS·retain·페이로드를 기록하고 콘솔에 토픽과 페이로드를 쓴다. 응답 메시지는 보내지 않는다. | 반영 | |
| `R01-R9` | 프로그램은 보내고 받은 모든 주고받음을 기록 폴더의 UTC 날짜별 파일 `dawon-fake-device-yyyyMMdd.jsonl`에 한 줄에 JSON 하나로 덧붙인다. 공통 필드는 `ts`·`channel`·`direction`·`kind`이고, `channel`별 `kind`는 `rest`: `request`·`response`·`error`·`verify` / `mqtt`: `connect`·`connack`·`subscribe`·`suback`·`publish`·`disconnect`·`error` / `fota`: `candidate`·`request`·`response`·`error`다. `direction`의 `device-to-dawon`은 가짜 장비가 보낸 것, `dawon-to-device`는 다원에서 받은 것이다. 본문·페이로드는 자르지 않으며, 올바른 UTF-8이 아니면 Base64로 기록하고 인코딩을 표시한다. REST는 요청 항목과 응답 항목(메서드·경로·본문, 응답은 상태 코드까지)으로, MQTT는 접속(ClientId·사용자명·비밀번호 유무·keepalive·clean session·Will), CONNACK, 구독, SUBACK, 발행(양방향), 종료로 남긴다. FOTA(`R01-R14`~`R01-R16`)는 요청 항목과 응답 항목(채널 `fota`)으로 남기며, 응답 항목에는 실제로 보낸 요청 URL(이미지 요청이면 접미사 포함)·상태 코드·`Content-Type`·`Content-Length`(없으면 없음)·받은 바이트 수·SHA-256·저장한 파일 이름을 담고, 응답 본문은 기록에 넣지 않고 200일 때 파일로만 둔다. `R01-R2`의 `verify` 판정, 연결 실패·시간 초과도 각각 항목으로 남긴다. 동시에 기록해도 줄이 섞이지 않는다. | 반영 | |
| `R01-R10` | 프로그램은 기록, 콘솔, 표준 오류에 비밀 값을 남기지 않는다. REST 응답 본문(JSON 객체)의 최상위 `mqtt_key`·`verify`는 `***`로 가리고, MQTT 비밀번호와 설정의 `mqtt_key`는 있는지 여부만 남긴다. | 반영 | |
| `R01-R11` | 종료 명령이나 Ctrl+C를 받으면 프로그램은 DISCONNECT를 보내 정상 종료하고, 종료 항목을 기록한 뒤 종료 코드 0으로 끝난다. 다원 쪽에서 접속이 끊기면 종료 항목(비정상 끊김)을 기록하고 0이 아닌 종료 코드로 끝난다. | 반영 | |
| `R01-R14` | 다원에서 받은 메시지(`R01-R8`)의 페이로드가 JSON이고 그 안의 문자열 값 가운데 `http://` 또는 `https://`로 시작하는 값이 있으면, 프로그램은 그 값을 FOTA URL 후보로 보고 콘솔에 쓰며 기록에 표시한다. 자동 받기 설정이 켜져 있으면 이미지 요청 하나 `GET {URL}{접미사}`를 보낸다. 접미사는 `R01-R1` 실행 슬롯의 반대편이며(실행 슬롯 2면 `_1`, 1이면 `_2`. `docs/reference/b540-fota.md` 4절의 추정 규칙), 받은 URL 문자열 끝에 그대로 붙인다. `/version` 요청과 접미사 없는 URL 요청은 보내지 않고, URL의 버전과 `R01-R1`의 펌웨어 버전은 비교하지 않는다. 다원이 주소·포트·경로를 나눠 보내 URL 후보가 없으면 FOTA 요청을 보내지 않는다(원문은 `R01-R8`대로 기록된다). 한 번 실행하는 동안 같은 URL은 한 번만 자동으로 받는다. | 반영 | |
| `R01-R15` | 콘솔 명령 `fota <URL>`을 받으면 프로그램은 `R01-R14`의 이미지 요청(`GET {URL}{접미사}`) 하나를 보내고, `get <URL>`을 받으면 주어진 URL을 가공하지 않고 그대로 `GET`한다. 같은 URL이라도 명령마다 다시 받는다. | 반영 | |
| `R01-R16` | `R01-R14`·`R01-R15`로 받을 때 프로그램은 모든 요청에 `Connection: keep-alive`와 `R01-R1` 설정의 `User-Agent`를 보낸다(`docs/reference/b540-fota.md` 3절의 고정 헤더). HTTP와 HTTPS를 모두 받고, `R01-R1`의 TLS 인증서 검증 설정을 따른다. 200이면 응답 본문을 기록 폴더 아래 `fota` 폴더에 요청마다 새 파일로 저장하고, 받은 파일은 실행하지 않는다. 200이 아니거나, 연결에 실패하거나, 60초 안에 끝나지 않거나, 본문이 4 MiB를 넘으면 그 요청의 받기를 멈추고 그 결과를 기록·콘솔에 남기며, 받은 데까지의 파일은 남기지 않는다. 받기가 실패해도 프로그램은 계속 실행하고, MQTT 처리와 정해진 발행은 받는 동안에도 멈추지 않는다. | 반영 | |
