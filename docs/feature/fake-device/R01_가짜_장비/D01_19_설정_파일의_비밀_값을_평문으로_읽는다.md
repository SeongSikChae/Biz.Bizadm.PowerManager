# D01_19 설정 파일의 비밀 값을 평문으로 읽는다

## 상황

설정 파일에 들어갈 비밀 값(선택 항목 `mqtt_key`, MQTT 비밀번호)을 어떻게 다룰지 정해야 했다. 기존 DeviceConfig 도구는 OS KMS로 암호화해 설정 파일에 다시 쓴다.

- 정한 단계: plan
- 관련: 옛 작업 스펙의 없음(D020으로 대체)(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 평문 설정: 설정 파일은 저장소 밖에 두는 로컬 시험용이라 평문으로 읽는다. 기록·콘솔에는 spec C10대로 남기지 않는다.

## 이유

- KMS 의존과 초기 설정이 없어 단순하다. B는 저장소 규칙과 같아지지만 OsKms 설정과 테스트가 늘어난다. (이 질문을 할 때는 규칙 `dotnet/kms-config-secrets.md`를 아직 읽지 않았다. `D01_20`(옛 D020)이 이 결정을 대체한다.)
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. DeviceConfig처럼 KMS 암호화: 기동 때 OS KMS로 암호화(`DEKENC:`)해 설정 파일에 다시 쓴다. | 위 「이유」에 함께 적힘 |

## 경위

- 2026-11-20 옛 작업 `docs/specs/dawon-fake-device/decisions.md`(지움. `15dc357`에 있음) D019에서 옮겼다(2026-11-23).
- 뒤에 `D01_20`(옛 D020)이 이 결정을 대신했다.

## 코드
