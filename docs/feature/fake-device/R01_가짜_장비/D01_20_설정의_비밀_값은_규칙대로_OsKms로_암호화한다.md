# D01_20 설정의 비밀 값은 규칙대로 OsKms로 암호화한다

## 상황

`D01_19`(옛 D019) 대체. 규칙 `dotnet/kms-config-secrets.md`는 설정 파일의 비밀 값을 평문으로 상시 보관하지 말고 Biz.Bizadm.KMS의 KEK + 로컬 DEK로 기동 때 암호화하며, 평문 우회 경로를 만들지 말라고 정한다. `D01_19`(옛 D019)는 이 규칙을 읽기 전에 고른 것이라 규칙과 충돌했다. `mqtt_key`·MQTT 비밀번호를 어떻게 할지 다시 정해야 했다.

- 정한 단계: plan
- 관련: 옛 작업 스펙의 plan.md 결정, 인터페이스·데이터(설정), 원칙 점검(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 규칙대로 OsKms: DeviceConfig.App과 같은 OsKms(OS 자격 증명 + 로컬 DEK)로 기동 때 암호화(`DEKENC:`)해 설정 파일에 다시 쓰고, 실행 때 복호화한다.

## 이유

- 저장소 규칙을 따르고, 같은 저장소의 DeviceConfig.App과 방식이 같다. B는 규칙 1·6번과 충돌한 채로 남는다. A는 비밀 값이 있을 때 OsKms 설정 섹션이 필요해지고 테스트가 늘어나는 것을 감수한다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
