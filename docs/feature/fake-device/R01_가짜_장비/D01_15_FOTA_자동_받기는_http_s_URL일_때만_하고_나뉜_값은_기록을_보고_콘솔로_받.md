# D01_15 FOTA 자동 받기는 http(s) URL일 때만 하고, 나뉜 값은 기록을 보고 콘솔로 받으며 그 URL은 추측으로 보지 않는다

## 상황

spec 검토 4회차 지적 5. 근거 문서 2절은 FOTA 정보를 `LFota_Url`·`LFota_Addr`·`LFota_Port`·`LFota_Version`처럼 나눠 두고 MQTT 쓰기도 같은 정보를 받는다고 추정한다. 다원이 나눠 보내면 어느 값도 `http(s)://`로 시작하지 않아 C14가 후보를 찾지 못하고, 나뉜 값을 사람이 이어 C15로 받는 것이 범위 밖의 "경로 추측"인지 기준도 없었다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 무엇을·왜, 범위 밖, C14(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 자동은 URL만, 나머지 수동: URL 후보가 없으면 자동으로 받지 않고(원문은 C8대로 기록됨) 기록을 보고 C15로 받는다. 범위 밖은 "다원이 보내지 않은 경로를 추측해 요청하는 것(다원이 보낸 값을 이어 붙인 URL은 추측이 아니다)"으로 고친다.

## 이유

- 리소스 ID가 미확인이라 어느 값이 주소·포트인지 몰라 자동 조합 규칙을 정할 수 없고, 정하면 그것이 추측이다. B는 잘못 조합한 요청을 다원에 보낼 수 있다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 조합도 자동 시도: 주소·포트·경로로 보이는 값을 조합해 자동으로 받는 규칙을 더한다. | 위 「이유」에 함께 적힘 |
