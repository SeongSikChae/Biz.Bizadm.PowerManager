# D01_12 FOTA 자동 받기의 두 번째 요청을 "URL 그대로 요청"으로 두고 이미지라고 단정하지 않는다

## 상황

spec 검토 4회차 지적 1. C14의 이미지 요청 `GET {URL}`이 근거 문서(`docs/reference/b540-fota.md` 3절: 버전 `GET %s/version`, 이미지 `GET %s%s` = 경로 + 이미지 이름)와 맞지 않는다는 의견이다. URL은 기준 경로일 수 있고, spec은 이미지 경로 규칙이 미확인이라면서 C14에서 규칙을 확정했다. 다만 같은 문서 2절은 `LFota_Url`을 "이미지 URL 또는 경로"로 적어 URL이 이미지 자체일 가능성도 있다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 무엇을·왜, C9, C13, C14, C15(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. URL 그대로 요청: 두 번째 요청을 "URL 요청 `GET {URL}`(URL이 이미지 자체일 수도 있어 그대로 받아 둔다)"으로 바꾸고 "장치처럼 이미지를 받는다"는 단정을 빼며, 이미지 이름 규칙은 미확인이라 기록을 보고 C15 단일 GET으로 받는다고 적는다.

## 이유

- URL이 이미지 자체일 수도 있어 바로 받아 두는 값이 있고, 근거와 다른 단정만 없앤다. B는 URL이 이미지 자체이면서 짧게만 유효하면 놓친다. C는 SDK 관례를 빌린 경로 추측 요청이라 범위 밖 원칙과 부딪히고, 덤프에서 그 파일 이름도 찾지 못했다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
