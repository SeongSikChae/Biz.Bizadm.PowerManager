# D01_18 기록기는 가짜 장비 프로젝트에 같은 형식으로 따로 둔다

## 상황

기록 형식은 중계 모드와 같아야 한다(spec C9). 그런데 중계 기록기 `DawonRelayRecorder`와 JSON 가림 도우미 `TopLevelJson`은 웹 앱 프로젝트 `Server.Spa` 안에 있고, 파일 이름 접두 `dawon-relay-`가 박혀 있다. 새 콘솔 프로그램에서 이 둘을 어떻게 쓸지 정해야 했다.

- 정한 단계: plan
- 관련: 옛 작업 스펙의 plan.md 결정, 바꿀 파일·구조(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 새 프로젝트에 따로 둠: 가짜 장비 프로젝트에 같은 형식의 기록기와 가림 도우미를 새로 둔다. 중계 코드는 손대지 않는다.

## 이유

- 중계 코드를 바꾸지 않으므로 확인받은 spec의 기능 범위(dawon-fake-device만)가 그대로다. B는 코드가 하나로 모이지만 dawon-relay 기능 파일을 바꾸게 되어, spec 기능 줄에 dawon-relay를 더하는 의도 변경이 되고 spec 검토·확인을 다시 해야 한다. A는 비슷한 코드(약 150줄)가 두 곳에 생기는 것을 감수한다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. Core로 옮겨 공유: 기록기와 `TopLevelJson`을 Core로 옮기고 파일 이름 접두를 인자로 받게 해 두 프로그램이 공유한다. | 위 「이유」에 함께 적힘 |

## 경위

- 2026-11-20 옛 작업 `docs/specs/dawon-fake-device/decisions.md`(지움. `15dc357`에 있음) D018에서 옮겼다(2026-11-23).
