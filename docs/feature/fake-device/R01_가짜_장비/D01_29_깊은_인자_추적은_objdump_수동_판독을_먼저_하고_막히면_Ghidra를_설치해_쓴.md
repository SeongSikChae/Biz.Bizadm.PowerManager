# D01_29 깊은 인자 추적은 objdump 수동 판독을 먼저 하고, 막히면 Ghidra를 설치해 쓴다

## 상황

plan 검토 3회차 지적 1. C2·C3의 핵심(형식 문자열의 베이스+오프셋 간접 참조, sprintf 인자 데이터플로)은 디컴파일러가 결정적으로 유리한데 plan은 objdump 수동 판독만 전제했다(검토 의견). 자매 문서 b540-mqtt-topic.md는 같은 작업을 Ghidra 12.2 headless(Xtensa:LE:32)로 했다. 메인 확인: 그 Ghidra는 이 원격 서버에 없고(analyzeHeadless·Xtensa 모듈 없음, Java 21만), 쓰려면 Ghidra + 서드파티 Xtensa 프로세서 모듈 설치가 필요하다.

- 정한 단계: plan
- 관련: 옛 작업 스펙의 plan.md 결정·인터페이스·데이터·검증 전략·원칙 점검(`docs/specs/b540-fota-path/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_02`

## 결정

- A. 단계적: objdump로 먼저 추적하고, 베이스+오프셋이 손으로 안 풀리면 그때 Ghidra+Xtensa를 설치해 디컴파일로 넘어간다.
- 옛 기록의 결정 칸: A(사용자 선택, 2026-11-20)

## 이유

- 요청 생성 함수 하나의 sprintf 인자(베이스 l32r + addi 오프셋)는 objdump로도 읽을 만하고, 막힐 때만 설치하면 설치 수고를 아끼면서 "C2·C3 미확인" 위험을 없앤다. B는 proven이지만 설치가 먼저 든다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
