# D01_32 FOTA 받기를 장치와 같은 한 요청으로 바꾼다

## 상황

가짜 장비의 FOTA 받기 요청 형식을 정해야 했다. 지금은 받은 URL로 `GET {URL}/version`과 `GET {URL}` 두 요청을 보내고, 2026-11-20 실제 다원 실행에서 둘 다 404였다. 슬롯 B 펌웨어 분석(`docs/specs/b540-fota-path/`(지움. `15dc357`에 있음))과 이번 사전 확인으로 실제 장치는 `/version` 요청 없이 `GET <경로><반대편 슬롯 접미사>` 하나만 보내고, 그 경로(`_1`·`_2`)는 다원 서버에서 200으로 이미지를 준다는 것을 확인했다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C1·C3·C5(`docs/specs/dawon-fake-device-fota-path/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_03`

## 결정

- A. 장치와 같게: 자동 받기(R14)와 콘솔 `fota` 명령(R15 첫째)이 `GET {URL}{접미사}` 하나만 보낸다. `/version` 요청과 기록의 버전 응답 본문 항목(R9)을 없앤다.
- 옛 기록의 결정 칸: A(사용자 선택, 2026-11-20)

## 이유

- A는 펌웨어 분석·실측과 같은 동작이라 실제 장치가 받는 것을 그대로 관찰하고, 늘 404인 요청이 사라진다. B는 늘 404인 요청 두 개가 남아 기록이 지저분하고 실제 장치 동작과 달라 고르지 않았다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 기존 유지 + 추가: 기존 두 요청(`/version`, 접미사 없는 URL)을 그대로 두고 장치 형식 요청을 세 번째로 더한다. | 위 「이유」에 함께 적힘 |
