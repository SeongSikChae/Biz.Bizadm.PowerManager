# D01_31 LFota_* 키→버퍼 매핑을 원격 디스어셈블로 재확인해 적는다

## 상황

구현 후 검토 1회차 지적 2. b540-fota.md 3절 2항이 "LFota_Url→host, LFota_Addr→path"를 관찰로 단정했는데 2절 추정 의미(Url=이미지 URL/경로, Addr=서버 주소)와 반대이고 작업 기록에 개별 매핑 근거가 약했다(검토 의견).

- 정한 단계: 구현
- 관련: 옛 작업 스펙의 b540-fota.md 2절 표·3절 2항(`docs/specs/b540-fota-path/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_02`

## 결정

- B. 원격 재확인: 원격 디스어셈블로 각 키의 strncpy 대상 버퍼와 그 버퍼의 역할을 다시 확인해 정확히 적는다.
- 옛 기록의 결정 칸: B(사용자 선택, 2026-11-20) - 재확인 결과(관찰): 설정 파서 0x4029d1a5가 LFota_Url→0x3fff1750, LFota_Addr→0x3fff17b5, LFota_Port→0x3fff181a, LFota_Version→0x3fff1820에 strncpy(각 키 l32r 4021d1a5/4021d219/4021d2cd 부근에서 버퍼 l32r 4021d1da/4021d24b/4021d2a6/4021d2ff). GET 빌더(4021e154)가 a4(첫 %s=GET 경로)=0x3fff17b5, a6(Host)=0x3fff1750을 쓰므로 0x3fff17b5=경로·0x3fff1750=host. 따라서 LFota_Url 값→host 필드, LFota_Addr 값→GET 경로 필드로 키 이름과 역할이 반대다. 2절 추정 의미를 이 관찰로 정정.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
