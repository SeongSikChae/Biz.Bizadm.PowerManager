# D01_10 FOTA를 범위에 넣고, 받은 메시지의 URL로 자동으로 받으며 콘솔 명령으로도 받는다

## 상황

사용자가 spec 확인 전에 FOTA도 대상으로 하자고 했다. 다원이 내려주는 펌웨어를 받으면 분석에 도움이 된다는 이유다. 근거 문서 `docs/reference/b540-fota.md`에 따르면 서버가 MQTT 쓰기로 URL을 보내고 장치가 `GET {URL}/version`과 이미지 `GET`을 하지만, 다원의 FOTA URL과 이미지 경로 규칙은 미확인이다. 다원이 보낸 URL을 어떻게 받을지 정해야 했다. 받은 파일은 저장만 하고 실행하지 않으며, 다원 서버 경로를 추측해 요청하는 것은 어느 선택지에도 넣지 않았다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 무엇을·왜, 범위 밖, C1, C7, C9, C12, C14, C15, C16(`docs/specs/dawon-fake-device/`(지움. `15dc357`에 있음)), 짝 태스크 `T01_01`

## 결정

- A. 자동 + 콘솔 명령: 받은 메시지의 값에 http(s) URL이 있으면 장치처럼 `GET {URL}/version`과 이미지를 받아 저장한다(설정으로 끌 수 있음). 이미지 경로 규칙이 미확인이라 콘솔에 URL을 직접 주어 받는 명령도 둔다.

## 이유

- URL이 짧은 시간만 유효해도 놓치지 않고, 자동 규칙이 맞지 않으면 명령으로 경로를 바꿔 받을 수 있다. B는 단순하지만 URL이 짧게만 유효하면 놓칠 수 있다. C는 펌웨어를 얻는다는 목적을 채우지 못한다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 콘솔 명령만: 자동으로 받지 않고, 기록에서 URL을 본 뒤 콘솔 명령으로 받는다. | 위 「이유」에 함께 적힘 |
| C. 기록만: 받기는 넣지 않고 FOTA 메시지 기록에서 멈춘다. | 위 「이유」에 함께 적힘 |
