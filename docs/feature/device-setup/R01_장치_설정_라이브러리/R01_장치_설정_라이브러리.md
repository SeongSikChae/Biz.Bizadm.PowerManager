# R01 장치 설정 라이브러리

## 목적

사용자가 B540 장치를 SoftAP TCP로 설정하려 한다. 라이브러리는 PC Wi-Fi를 장치 AP로 바꿔 접속하고, 설정 명령을 장치 프로토콜대로 주고받은 뒤, 결과와 관계없이 PC Wi-Fi를 원래대로 돌려놓는다. 콘솔 App(`R02`)과 MCP 서버(`R03`)가 이 라이브러리를 쓴다.

## 요구사항

| ID | 요구사항 | 상태 | 일감 |
| --- | --- | --- | --- |
| `R01-R1` | 실행하면 `DeviceConfigRunner`는 무선 어댑터 선택 → 접속 전 SSID 기억 → `Device.ApPrefix`로 시작하는 장치 AP 선택 → 개방형 접속과 IPv4 게이트웨이 대기(`ApConnectTimeoutSeconds`) → `Commands`를 순서대로 실행(명령마다 TCP 연결 → 핸드셰이크 → 명령 → 연결 종료) 순으로 동작하고, 장치 AP 접속을 시도했으면 성공·실패·취소와 관계없이 PC Wi-Fi를 접속 전 상태로 복구한다. | 반영 | |
| `R01-R2` | PC Wi-Fi 호출이 `NotImplementedException`(미구현 OS)이면 `DeviceConfigRunner`는 경고를 남기고 `Device.Host`로 접속한다. 그 밖의 PC Wi-Fi 실패이면 실행을 멈춘다. | 반영 | |
| `R01-R3` | 장치에 연결하면 라이브러리는 연결마다 `[DUT<-PC] START\n` → `hello tcp SUCCESS_CONNECT\n`을 보내고 `[DUT->PC] START_OK:<mac>#`에서 MAC을 얻는다. 수신 프레임은 `#` 프레임과 JSON(중괄호 짝)으로 나누고 `BUTTON_…#` 이벤트 프레임은 건너뛴다. 흐름 V4의 `ConnectAp`는 `START_OK` 앞에 오는 다른 프레임을 최대 2개 건너뛰고(3개째도 아니면 실패), 그 밖에는 첫 프레임이 `START_OK`가 아니면 실패한다. | 반영 | |
| `R01-R4` | 라이브러리는 명령 `ApScan`·`Reboot`·`FactoryReset`·`ScanAp`·`OnCmd`·`OffCmd`·`Measurement`·`OverLoad`·`TestFactoryReset`을 `C01-I1` 명령 표의 송신·응답 형식으로 실행한다. `Reboot`·`TestFactoryReset`은 응답이 없거나 연결이 끊겨도 경고 후 성공으로 본다. 응답 형식이 다르면 실패로 본다. | 반영 | |
| `R01-R5` | `ConnectAp`를 실행하면 라이브러리는 한 연결에서 핸드셰이크 → `{"command":"apscan"}` → Wi-Fi 선택 → 설정 JSON을 보낸 뒤 흐름(`R01-R10`)별로 마무리한다. V1: 응답을 기다리지 않고 정상 종료 / V2: 응답 프레임 하나를 받고(내용은 검사하지 않음) `{"delay":"0"}`을 보낸 뒤 정상 종료 / V3: `{"mac":"<mac>","command":"connectap"}`을 보내고 설정 JSON과 `connectap` 응답이 모두 `respone` `OK`여야 성공 / V4: 응답을 기다리지 않고 `connectap`을 보낸 뒤 정상 종료. 정상 종료는 송신을 끝내고 장치가 연결을 닫을 때까지 남은 수신을 읽어 비운 뒤(로그만, 검사 없음) 닫는 것이다. Wi-Fi 후보는 등록 `WifiProfiles` 중 장치 `apscan` SSID와 대소문자까지 같은 것을 RSSI 높은 순으로 고르며, 후보가 없으면 설정을 보내지 않고 실패한다. | 반영 | |
| `R01-R6` | 라이브러리는 흐름 V2~V4의 설정 JSON을 키 `mac`, `api_server_addr`, `api_server_port`, `server_addr`, `server_port`, `ssl_support`, `ssid`, `pass`, `user_id`, `company`, `model`, `lati`, `long`, `topic` 순서로, `mqtt_key` 없이 만든다(참고 구현 `MqttConfigurationV2`). V1은 `server_addr`, `server_port`, `ssl_support`, `ssid`, `pass`, `mqtt_key`, `company`, `model`, `topic`이다(참고 구현 `MqttConfiguration`). 값은 모두 문자열이고 `ssl_support`는 `yes`/`no`다. | 반영 | |
| `R01-R7` | 라이브러리는 설정 JSON을 `System.Text.Json` 기본 인코더로 직렬화한다(`+ & < > '`와 비ASCII는 `\uXXXX`). | 반영 | |
| `R01-R8` | 라이브러리는 송수신 메시지를 Information 로그로 남기되 설정 JSON의 `pass`·`mqtt_key`는 `***`로 가린다. 실제 `pass`·`mqtt_key`(원문·이스케이프된 형태)는 로그·예외 메시지에 남지 않는다(`DeviceSettings.ToString`도 `MqttKey`를 가린다). | 반영 | |
| `R01-R9` | 응답을 기다리는 단계에서 라이브러리는 단계마다 `Device.TimeoutSeconds`를 기다린다. 시간 초과이면 `TimeoutException`, 응답 전 연결 종료이면 `IOException`으로 실패하며, 명령 하나가 실패하면 남은 명령을 실행하지 않는다. 응답을 기다리지 않는 흐름(`R01-R5`의 V1·V2·V4 마무리)의 정상 종료 중 수신 비우기는 `Device.TimeoutSeconds` 안에 장치가 닫지 않아도 실패로 보지 않는다. | 반영 | |
| `R01-R10` | 라이브러리는 `ConnectAp` 흐름을 `DeviceSettings.Protocol`(`V1`·`V2`·`V3`·`V4`, 기본 `V3`)로 고른다. V1인데 `DeviceSettings.MqttKey`(복호화된 값)가 없으면 `DeviceConfigRunner`는 PC Wi-Fi를 장치 AP로 바꾸기 전에, `DeviceClient`는 장치에 접속하기 전에 `InvalidOperationException`으로 실패한다. | 반영 | |

| `R01-A5` | `R01-R5` | 흐름 V1~V4마다 모의 장치가 받은 메시지 순서와 마무리가 요구와 같고, V3은 두 응답 중 하나라도 `OK`가 아니면 실패하며, `apscan`에 등록 SSID가 대소문자까지 같은 것이 없으면 설정 JSON이 송신되지 않고 실패한다. | `V01_03` |

| `R01-A7` | `R01-R7` | `+ & < > '`와 한글이 든 값을 넣으면 설정 JSON에 `\uXXXX`로 이스케이프되어 나간다. | `V01_02` |

| `R01-A10` | `R01-R10` | `Protocol` 없이 실행하면 V3 흐름이 쓰인다. V1인데 `MqttKey`가 없으면 `DeviceConfigRunner`는 PC Wi-Fi를 바꾸지 않고, `DeviceClient`는 장치에 접속하지 않고 `InvalidOperationException`으로 실패한다. | `V01_03` |

## 지금 동작

- `ConnectAp` 흐름 V1~V4는 참고 구현 PowerManagerConfig의 `ConfigratorV1`~`V4`를 옮긴 것이다. 실장비(B540)로 확인한 흐름은 기본 V3뿐이고, V1·V2·V4는 모의 장치로만 확인했다.
- V3 설정 JSON을 받은 실장비는 약 4~6초 뒤 공유기에 붙어 `dwapi.dawonai.com`을 조회하고 서버에 `POST /api/v1/devices/register/create`를 보낸다.
- `Reboot`·`TestFactoryReset`은 실장비 B540에서 응답·연결 종료 없이 시간 초과였고, 약 40초 뒤 장치 AP가 다시 나타났다.
- 장치 송수신은 UTF-8이며 한글 등 비ASCII SSID는 지원하지 않는다(장치가 보내는 바이트 형식 미확인).
- 실장비 테스트(`[TestCategory("Device")]`)는 기본 `dotnet test`에서 빠진다. 실행은 `dotnet test -p:TestingPlatformCommandLineArguments= --filter "TestCategory=Device"`이며 장치 초기화·PC Wi-Fi 변경 위험이 있다.
- 공유기가 장치 SoftAP와 같은 채널이면 `apscan`에 빠질 수 있어, 후보가 없을 때 채널을 바꿔 다시 시도하라는 로그를 남긴다.
