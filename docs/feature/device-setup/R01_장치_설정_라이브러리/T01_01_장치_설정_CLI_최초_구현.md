## 할 일

### 단계 1: 솔루션 골격 (U1)
- 기존 프로젝트를 지우고 DeviceConfig·HostWifi 런타임 셋·App·테스트 프로젝트를 만든다.

확인: `dotnet build Biz.Bizadm.PowerManager.slnx` 경고 0, `dotnet publish -r linux-x64`·`-r osx-arm64` 출력에 각 스텁의 `HostWifi.Runtime.dll` 하나.

### 단계 2: 프로토콜 (U2)
- `START_OK` 파싱, `respone` 판정, `SCAN_AP_LIST` 파싱, 설정 JSON·마스킹(`R01-R3`, `R01-R4`, `R01-R8`).

확인: `DeviceConfig.Tests`의 프로토콜 단위 테스트 통과.

### 단계 3: 전송 (U3)
- `DeviceFrameReader`(조각 입력, `#`/JSON 판별, BUTTON 프레임), 명령마다 새 연결, `ConnectAp` 한 연결 순서, 시간 초과·연결 종료 예외(`R01-R3`~`R01-R5`, `R01-R9`).

확인: `DeviceFrameReaderTests`, `MockDevice`를 쓰는 `DeviceClientTests` 통과. 로그·예외에 `pass` 평문 없음.

### 단계 4: HostWifi·Runner (U4~U6)
- `HostWifiLoader`, `DeviceConfigRunner`(게이트웨이 대기, 복구, `NotImplementedException` 폴백), Wi-Fi 대조, Windows WLAN 구현(`R01-R1`, `R01-R2`, `R01-R5`).

확인: 모의 `IHostWifi`·선택기 테스트로 복구·폴백·전파 경로, `Device` 카테고리 테스트로 실제 어댑터 목록·`DWD-` 스캔·게이트웨이 `192.168.244.1`·복구.

### 단계 5: App (U7)
- YAML 설정 검사, OsKms 암호화, 콘솔 번호 선택, 종료 코드(`R02-R1`~`R02-R5`).

확인: 빌드한 exe로 인자 없음 1, 설정 오류 2, 표준 입력 EOF 3, 평문 `Pass`가 `DEKENC:`로 다시 기록됨.

### 단계 6: 실장비 전체 명령 (U8)
- 장치 상태를 덜 바꾸는 순서로 모든 명령을 실행하고 `Reboot`·`TestFactoryReset`의 응답 없음 처리를 정한다(`R01-R4`).

확인: 명령마다 결과와 SoftAP 복귀를 기록, 연속 명령 실행, 종료 코드 0과 3.

## 위험

- PC Wi-Fi 접속 확인이 SSID만 보면 연결 시도 중에도 접속으로 보일 수 있다. 실장비(#2)에서 확인해 현재 연결 SSID와 게이트웨이를 함께 본다.
- `Reboot`·초기화의 실동작(장치가 실제로 재부팅·초기화되는지)은 이 작업에서 확인하지 않았다(#3으로 분리).
