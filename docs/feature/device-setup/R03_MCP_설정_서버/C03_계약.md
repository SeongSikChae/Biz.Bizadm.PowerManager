## C03-I1 MCP 설정 파일(YAML)

입력

- 모양은 코드의 `McpConfiguration`과 섹션 클래스를 따르고, 필수·기본값·범위는 `R03-R2`·`R03-R6`에 있다. `Http.Port`는 기본값이 없다.

출력

- 기동하면 `WifiProfiles.Pass`·`Settings.MqttKey`의 평문이 `DEKENC:`로 다시 쓰인다.

오류

| 코드 | 나는 조건 |
| --- | --- |
| 종료 코드 2 | `ContentRootPath`·`OsKms`·`Http` 없음, `Http.Port` 범위 밖, `Settings.Protocol` 틀림(V1·`MqttKey` 없음은 기동을 막지 않음) |

권한

- 서버를 실행하는 OS 계정(서비스면 OsKms 자격 증명을 가진 로그인 계정)

코드

- `src/Biz.Bizadm.PowerManager.DeviceConfig.Mcp/McpConfiguration.cs`, `Security/ConfigSecretProtector.cs`

## C03-I5 `run_device_commands`

입력

| 이름 | 형 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `adapterId` | 문자열 | 예 | `list_wifi_adapters`의 `id` |
| `deviceApSsid` | 문자열 | 예 | `scan_device_aps`에서 고른 대상 장치 AP SSID |
| `commands` | 문자열 배열 | 예 | `DeviceCommand` 이름과 정확히 일치 |
| `wifiSsid` | 문자열 | `ConnectAp`만 | 등록 `WifiProfiles` 가운데 하나 |
| `settings` | 객체 | 아니오 | `SettingsOverride`. null이 아닌 필드만 설정 파일 값을 덮어씀. `protocol` 포함, 모르는 키(`mqttKey`, `user_id` 등)는 거부 |

출력

- `RunResult`(`success`, `results[]`: `command`·`response`, `error`(성공이면 생략, required 아님)). 시작과 명령 완료마다 진행 알림

오류

| 코드 | 나는 조건 |
| --- | --- |
| `success: false` + `error` | 모르는 명령, 빈 명령, Wi-Fi·인자 오류, `settings` 모르는 키·누락·범위, V1인데 `MqttKey` 없음(모두 Wi-Fi 접속 전), 실행 중 명령 실패(완료된 결과 포함) |
| 예외(isError) | 인자 형 불일치(SDK 바인딩), 취소 |

권한

- `C03-I2`와 같음. destructive, openWorld. PC Wi-Fi를 쓰므로 프로세스 안에서 하나씩 실행

코드

- `src/Biz.Bizadm.PowerManager.DeviceConfig.Mcp/DeviceConfigTools.cs`, `DeviceConfigService.cs`(`SettingsOverride`, `CommandResult`, `RunResult`), `ParameterDeviceConfigSelector.cs`

바뀔 것

- 없음
