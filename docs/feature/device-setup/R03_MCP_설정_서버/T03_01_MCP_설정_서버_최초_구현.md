## 할 일

### 단계 1: Runner 명령별 결과 통보 (U1)
- 명령 하나가 끝날 때마다 결과(`DeviceCommandResult`)를 알린다(`R03-R8`의 진행 알림 바탕).

확인: `Run_ReportsEachCompletedCommand`, `Run_CommandFails_ReportsOnlyCompleted`, `Run_ConnectAp_ReportsSelectedSsid` 통과, App 빌드 통과.

### 단계 2: MCP 프로젝트·설정·KMS·기동 (U2)
- 설정 검사, OsKms 암호화, 실행 인수와 종료 코드(`R03-R5`, `R03-R6`).

확인: `McpConfigurationTests` 통과. exe 실측: 인수 없음 1, 없는 설정 파일 2.

### 단계 3: 인자 선택기 (U3)
- 어댑터·장치 AP·Wi-Fi를 tool 인자로 고르는 `ParameterDeviceConfigSelector`.

확인: 일치(어댑터 ID 대소문자 무시)·불일치 예외 메시지·`wifiSsid` null 예외 테스트 통과.

### 단계 4: tool (U4)
- tool 넷과 직렬 실행, 조회 실패의 isError, 명령 이름 정확히 일치, `ConnectAp` 사전 검사(`R03-R7`~`R03-R9`).

확인: `DeviceConfigServiceTests`(성공·진행 알림·중간 실패·`ConnectAp` 사전 검사·모르는 명령·취소·동시 호출 직렬화·`pass` 로그 없음) 통과.

### 단계 5: 통합 테스트·수동 확인 (U5)
- exe를 띄워 MCP SDK 클라이언트로 `tools/list`·`tools/call`.

확인: `dotnet test --solution` 전체 통과, `-warnaserror` 경고 0. 2026-11-11 SDK 클라이언트로 tool 4개, 어댑터 1개, 장치 AP 5개, B540 실장비 1 `Measurement` 성공과 PC Wi-Fi 복구.

## 위험

- 30초를 넘는 실행 중 클라이언트 연결이 끊기는 경우, MCP 경로의 "이전 SSID로 재연결"은 확인하지 못했다.
