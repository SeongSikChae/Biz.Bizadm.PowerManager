# D04_54 장비명은 앞뒤 공백을 없앤 뒤 검사한다

## 상황

spec 검토 1회차 지적 3. C11과 C15에서 제어 문자·줄 구분 문자를 공백을 없애기 전에 보는지 뒤에 보는지, 공백이 무엇인지 정하지 않았다. `"거실\n"`과 `"\t"`의 결과가 갈리고, JS `trim`과 .NET `Trim`이 U+FEFF·U+0085에서 달라 화면과 서버 판정이 갈릴 수 있었다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C11, C15(`docs/specs/device-name-and-units/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_03`

## 결정

- A. 공백을 없앤 뒤 검사: 앞뒤 공백(.NET `char.IsWhiteSpace`가 참인 문자)을 먼저 없애고 그 값으로 길이와 문자를 검사하며, 화면도 같은 문자를 없앤다. `"거실\n"`은 저장, `"\t"`는 이름 삭제, `"거\n실"`은 400이다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 검사한 뒤 공백 제거: 제어·줄 구분 문자는 앞뒤에 있어도 거부하고 그 뒤 공백을 없애 길이를 검사한다. | 사용자가 말하지 않음 |
