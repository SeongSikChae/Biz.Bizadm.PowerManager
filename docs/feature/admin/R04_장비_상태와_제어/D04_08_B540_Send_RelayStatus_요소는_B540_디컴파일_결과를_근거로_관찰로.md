# D04_08 B540 `Send_RelayStatus` 요소는 B540 디컴파일 결과를 근거로 관찰로 적는다

## 상황

구현 후 검토 3회차 지적 2. 새 문서 3.1·3.3·3.4·7절이 B540 `Send_RelayStatus`(`0x402caa88`)가 `/100/0/31`·`/100/0/32`를 보낸다고 관찰로 적었지만 B540 함수는 디컴파일하지 않았고(요소는 M130-W `0x4024d280`에서만 확인), 6절 「장치 → 서버 보고」 행은 "M130-W 관찰"이라 문서 안 근거 표기가 어긋났다. 7절 B540 시계 확인은 이 요소와 원인 값을 판정 기준으로 쓴다.

- 정한 단계: 구현
- 관련: 옛 작업 스펙의 mqtt-device-control.md 3.1 자동 복구 항목, 3.3 「다시 켠 뒤」, 6절 「장치 → 서버 보고」 행, 7절 B540 시계 행(`docs/specs/device-control-ref/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_01`

## 결정

- A. 디컴파일 근거로 표기 맞춤: B540 `0x402caa88`을 디컴파일해(검토 판단 전에 확인함: 연결 중 `notify`로 `/100/0/31`·`/100/0/32`) B540 관찰을 유지하고, 6절 행을 두 모델 함수 관찰로, 7절 기대값을 `/100/0/32` `"16"`으로 고친다.

## 이유

- A는 확인이 이미 끝나 문구 몇 곳만 고치면 되고 근거가 관찰로 남는다. B는 이미 확인한 사실을 추정으로 낮춰 고르지 않았다. 고치지 않음은 문서 안 근거 표기 불일치가 남아 고르지 않았다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
