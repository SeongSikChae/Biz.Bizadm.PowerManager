# D04_19 설정 값은 서버 메모리에만 두고, 예약 저장은 항상 `U`, 삭제는 항상 받는다

## 상황

spec 검토 1회차 지적 5. 서버가 마지막으로 보낸 설정 값이 메모리에만 있어 서버를 다시 시작하면 "보낸 적 없음"이 된다. 처음 spec은 그때 예약 삭제를 404로 막고 버튼도 비활성으로 둬, 장치에 남은 예약을 지울 수 없었다. 또 그때 저장하면 `I`를 보내는데, 같은 번호 항목이 이미 있는 장치의 `I` 처리는 근거에 없다(근거 문서 3.3이 관찰한 것은 "`U`인데 기존 항목이 없으면 `I`로 바꿔 처리"뿐). 삭제 메시지의 나머지 항목 값도 정해지지 않았고, 설정 값의 메모리 보관은 `D04_13`(옛 D005)(최신 상태만 다룸)에 들어 있지 않았다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 「확정한 결정」, 범위 밖, C12, C13, C26(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- A. 메모리 유지: 저장은 항상 `U`를 보내고, 삭제는 서버 기록과 상관없이 받아 고정 문자열 `"1,D,F,0,1111111,00:00:00,F,0"`을 보낸다. 설정 값은 서버 메모리에만 둔다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
