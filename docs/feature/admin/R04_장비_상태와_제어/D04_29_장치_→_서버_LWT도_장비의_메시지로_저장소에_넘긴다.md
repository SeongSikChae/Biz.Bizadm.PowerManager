# D04_29 장치 → 서버 LWT도 장비의 메시지로 저장소에 넘긴다

## 상황

tasks 검토 1회차 지적 2. tasks.md T010은 저장소에 넘기는 메시지에서 LWT를 뺐다. 그러나 plan.md는 LWT를 빼지 않았고, spec.md 용어는 장비의 메시지를 장치 → 서버 토픽(mqtt-broker R2)으로 온 메시지로 정의하며, `{prefix}.v1/{deviceKey}/iot-server/lwt`도 그 토픽이다(`MqttBrokerHostedService.OnPublishAsync`가 `DeviceTopicKind.Lwt`로 해석).

- 정한 단계: tasks
- 관련: 옛 작업 스펙의 tasks.md T010(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- A. "LWT 제외"를 지움: LWT는 페이로드를 해석하지 않고 토픽과 ClientId만 저장소에 넘긴다(C3 토픽 기억, C30 판정 대상). tasks.md만 고친다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. LWT를 빼고 spec에 예외를 적음: spec 용어(또는 C3)와 plan에 LWT 제외를 적는다(확인받은 spec의 의도 변경). | 사용자가 말하지 않음 |

## 경위

- 2026-11-22 옛 작업 `docs/specs/device-control/decisions.md`(지움. `15dc357`에 있음) D021에서 옮겼다(2026-11-23).
