# D04_32 사용자 속성 대안을 버린 이유를 확인한 사실로 바꾼다

## 상황

plan 검토 5회차 지적 2. plan.md 결정(`sid`로 짝짓기)의 검토한 대안은 "MQTT 5 사용자 속성은 장비가 MQTT 3.1이라 쓸 수 없다"고 적었다. 그러나 짝짓기는 서버 안의 큐 넣음 이벤트에서만 하므로 장비 프로토콜은 이유가 되지 않는다. MQTTnet.Server 5.2.0.1603에 `V310` 구독자를 붙이고 사용자 속성을 넣은 메시지를 주입해 실행하니 큐 넣음 이벤트에서 그 속성이 읽혔다. 설계와 동작에는 영향이 없으나 대안을 버린 이유가 사실과 다르게 남는다.

- 정한 단계: plan
- 관련: 옛 작업 스펙의 plan.md 결정(`sid`로 짝짓기)(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- A. 확인한 사실로 바꿈: 사용자 속성은 큐 넣음 이벤트에서 읽히지만, 제어 메시지에는 C14 로그에 남길 `sid`가 이미 있어 표시를 하나 더 둘 까닭이 없다고 적는다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 문장을 지움: 사용자 속성 문장만 지우고 객체 참조 비교 대안은 남긴다. | 사용자가 말하지 않음 |
