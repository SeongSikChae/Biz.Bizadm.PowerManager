## 항목

| ID | 이름 | 종류 | 상태 |
| --- | --- | --- | --- |
| `C04-E1` | 장비 상태(`DeviceState`와 응답 원소 `DeviceStatusResponse`) | 엔티티 | 반영 |

## 호환 규칙

- 바꿔도 되는 것: 새 응답 필드, ProblemDetails 문구
- 바꾸려면 결정 문서가 있어야 하는 것: 경로, 요청·응답 필드 이름, 판정 순서와 상태 코드, 이벤트 이름(`snapshot`·`device`), 제어 메시지의 오퍼레이션·리소스·값 형식(장치 펌웨어가 읽음), 입력 범위

## C04-E1 장비 상태

필드

- 서버 안: `DeviceState`(온라인, 릴레이 `RelayState`, 계량 값, 마지막 보고 시각, 토픽 접두·장치 키, 이번 접속의 릴레이 읽기 여부). 응답: `DeviceStatusResponse`(`mac`, `name`, `modelId`, `online`, `relay`, `voltage`, `current`, `powerFactor`, `power`, `lastReportAt`, `controllable`).

불변 조건

- 메모리에만 있고 서버를 다시 시작하면 사라진다.
- `relay`는 `on`·`off`·`unknown`, 보고가 없으면 `unknown`과 계량 값·`lastReportAt` null이다.
- `controllable`은 온라인이고 토픽 접두·장치 키를 알 때만 참이다.
- 응답에 MQTT 키가 없다.

상태 전이

- `relay`: `unknown` → `on`/`off`(상태 보고), `on` ↔ `off`. `online`: 접속 → 참, 끊김 → 거짓(`Takeover`는 그대로).

코드

- `src/Biz.Bizadm.PowerManager.Server.Spa/Devices/DeviceStateStore.cs`(`DeviceState`, `RelayState`), `DeviceStatusResponse.cs`, `DeviceStatusService.cs`

## C04-E2 마지막으로 보낸 설정

필드

- `DeviceSettingsResponse`(`reportCondition`, `standbyCutoff`, `schedule`. 각각 `ReportConditionSettings`, `StandbyCutoffSettings`, `ScheduleSettings` 또는 null)

불변 조건

- 성공한(전송 큐에 들어간) 제어만 남긴다. 장치의 실제 값과 다를 수 있다.
- 예약 삭제가 성공하면 `schedule`은 null이다.
- 메모리에만 있다(설정 보관과 장치에서 읽기는 GitHub #29).

상태 전이

- 항목마다 null → 값 → 값(덮어씀), `schedule`만 값 → null(삭제)

코드

- `src/Biz.Bizadm.PowerManager.Server.Spa/Devices/DeviceSettingsModels.cs`, `DeviceStateStore.cs`

## C04-I3 제어 API

입력

| 이름 | 형 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `POST .../relay` | `RelayRequest(on)` | 예 | `R04-R8` |
| `POST .../power-cycle` | `PowerCycleRequest(seconds)` | 예 | 1~999(`R04-R9`) |
| `POST .../reboot` | 본문 없음 | 예 | `modelId`가 `B540`으로 시작할 때만(`R04-R10`) |
| `PUT .../report-condition` | `ReportConditionRequest(minInterval, maxInterval, changeThreshold)` | 예 | 범위는 `R04-R11` |
| `PUT .../standby-cutoff` | `StandbyCutoffRequest(enabled, thresholdWatts, delay)` | 예 | 범위는 `R04-R12` |
| `PUT .../schedule` | `ScheduleRequest(enabled, days[7], time, seconds)` | 예 | `days`는 일~토 순서, 규칙은 `R04-R13` |
| `DELETE .../schedule` | 없음 | 예 | 보낸 예약이 없어도 받음 |

출력

- 204(전송 큐에 들어감. 장치가 받았거나 처리했다는 뜻이 아님). 제어 메시지는 `device-server/C02-I2`·`device-server/C02-I4`로 보낸다.

오류

| 코드 | 나는 조건 |
| --- | --- |
| 400 | mac 형식(1순위), 본문 범위·모델(3순위) |
| 404 | 등록되지 않은 mac(2순위), 장치 포트로 부름 |
| 409 | 제어 가능하지 않음(4순위), 전송 큐에 넣지 못함(5순위) |

권한

- 관리 포트만, 인증 없음

코드

- `src/Biz.Bizadm.PowerManager.Server.Spa/Devices/AdminDeviceControlController.cs`, `DeviceCommandService.cs`, `DeviceSettingsModels.cs`
