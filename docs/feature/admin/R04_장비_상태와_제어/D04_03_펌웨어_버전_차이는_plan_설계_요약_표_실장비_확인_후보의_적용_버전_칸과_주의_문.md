# D04_03 펌웨어 버전 차이는 plan 설계(요약 표·실장비 확인 후보의 적용 버전 칸과 주의 문구)로 다룬다

## 상황

plan 검토 1회차 지적 2. B540 분석 이미지는 `1.01.34`인데, 서버 로그로 관찰한 B540 실장비는 펌웨어 `1.01.36`이다(`docs/reference/b540-mqtt-topic.md` 4절). 그런데 spec C7과 plan 「인터페이스·데이터」 8절은 실장비 확인 후보 메시지가 어느 펌웨어 버전 기준인지 적게 하지 않는다. 나중 작업이 1.01.34 기준 오퍼레이션·경로를 1.01.36 장치에 그대로 보내면, 결과가 어긋나도 버전 차이 때문인지 분석 오류 때문인지 가릴 수 없다. 상태를 바꾸는 메시지(릴레이·재부팅)라면 의도와 다른 동작을 일으킬 수도 있다. M130-W는 분석 이미지와 관찰 실장비가 모두 `2.01.58`이다.

- 정한 단계: plan
- 관련: 옛 작업 스펙의 plan.md 결정 「펌웨어 버전 표기」, 「인터페이스·데이터」 1·3·8절(`docs/specs/device-control-ref/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_01`

## 결정

- A. plan만 고침: plan 「인터페이스·데이터」 3절(요약 표)과 8절(실장비 확인 후보)에 적용 펌웨어 버전을 적게 하고, 머리말과 8절에 B540 실장비 `1.01.36` 관찰과 "1.01.34 분석을 다른 버전에 쓸 때는 차이가 있을 수 있다"는 주의를 적게 한다. 확정한 spec은 그대로 둔다.

## 이유

- 문서에 버전과 주의를 적게 하려는 목적은 설계(문서 절 구성)로 충분히 이루어지고, 확정한 spec을 다시 검토·확인받는 비용을 피한다. B는 완료 조건으로 강제할 수 있지만 spec 단계부터 다시 해야 해 비용이 커 고르지 않았다. 고치지 않음은 1.01.34 기준 메시지를 1.01.36 장치에 그대로 보낼 위험이 남아 고르지 않았다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. spec C5·C7까지 고침: 완료 조건에 "항목마다 적용 펌웨어 버전과 실장비 관찰 버전 차이를 적는다"를 더하고 plan도 맞춘다. 확정한 spec을 바꾸는 의도 변경이라 spec 검토·사용자 확인부터 다시 한다. | 위 「이유」에 함께 적힘 |
