# D04_06 plan·tasks의 절 번호를 새 문서의 실제 번호(머리말 뒤 1~7절)에 맞춘다

## 상황

구현 후 검토 1회차 지적 10. 새 문서는 머리말 뒤에 1~7절로 번호를 매겼는데, plan 「결정 — 분석 이미지」의 "2절에 적는다"와 「인터페이스·데이터」 목록(1~8), tasks T006~T012의 절 번호는 예전 번호(머리말=1절)라, 그 번호로 검증하면 다른 절을 보게 된다. plan은 "번호는 쓰면서 맞춘다"고 했고 내용은 같다.

- 정한 단계: 구현
- 관련: 옛 작업 스펙의 plan.md 「결정」 분석 이미지·펌웨어 버전 표기, 「인터페이스·데이터」 목록, 「검증 전략」 C1, tasks.md T006~T012·단계 2 체크포인트(`docs/specs/device-control-ref/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_01`

## 결정

- A. plan·tasks 번호를 문서에 맞춤: plan의 규칙 위치를 1절로, 「인터페이스·데이터」 목록을 머리말·1~7절로, 검증 전략 C1을 1절로, tasks T006~T012와 체크포인트의 절 번호를 문서 번호로 바꾼다. 내용은 바꾸지 않는다.

## 이유

- A는 두 문서의 번호 교체뿐이고 내용이 바뀌지 않아 규칙상 고치기만 하면 되는 수정이다. B는 제목 7개와 앵커 링크 수십 곳을 고쳐야 해 링크가 깨질 위험이 있어 고르지 않았다. 고치지 않음은 검증 때 다른 절을 보게 되어 고르지 않았다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 문서 번호를 plan에 맞춤: 새 문서 머리말을 1절로 두고 나머지를 2~8절로 다시 매기며 앵커 링크를 모두 고친다. | 위 「이유」에 함께 적힘 |
