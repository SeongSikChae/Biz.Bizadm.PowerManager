# D04_17 서버 재시작 뒤 릴레이 상태는 서버가 한 번 읽고, 모르는 동안에는 켜기·끄기 버튼으로 제어한다

## 상황

spec 검토 1회차 지적 2. 주기 보고(`Report`)의 요소에는 `/100/0/30`·`31`이 없다(근거 문서 4.3). 릴레이 요소는 `Send_FirstRelay`(조건 플래그가 0일 때 한 번), `e` 응답, `Send_RelayStatus`에만 있고, 그 플래그가 재접속 때 0으로 돌아가는지 근거에 없다. 그런데 spec은 릴레이 스위치를 "릴레이 상태를 아는 장비에서만" 누를 수 있게 해, 서버를 다시 시작하면 릴레이를 켜고 끌 방법이 없어질 수 있었다. 또 토픽 정보를 상태 보고에서만 배우게 돼 있어, 접속 직후의 `tisyn`만 온 장비는 제어할 수 없었다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 「확정한 결정」, C3, C30, C19, C21, C22, C25(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- C. 둘 다: B로 채우고, 그래도 모르는 동안에는 A의 버튼으로 제어한다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| A. 모를 때 켜기·끄기 버튼: 릴레이 상태를 모르면 스위치 대신 "켜기"·"끄기" 버튼을 보이고(끄기는 확인 창), 상태를 알게 되면 스위치로 바꾼다. 서버는 읽지 않는다. | 사용자가 말하지 않음 |
| B. 서버가 `r`로 읽기: 장비의 토픽 정보를 알았는데 릴레이 상태를 모르면 서버가 `r` `/100/0/30`을 한 번 보낸다. | 사용자가 말하지 않음 |
