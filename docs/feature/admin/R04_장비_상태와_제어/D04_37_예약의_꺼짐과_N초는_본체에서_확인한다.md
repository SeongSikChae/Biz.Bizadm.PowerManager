# D04_37 예약의 꺼짐과 N초는 본체에서 확인한다

## 상황

spec 검토 5회차 지적 2. 「확정한 결정」은 예약으로 끌 때 알리지 않는 것을 관찰했다고 적었으나, 로그에는 다시 켤 때의 보고만 있고 실제로 꺼진 기록이 없다. 켜기 판정(B540 `1.01.34` `0x4029b2d2`~`0x4029b307`)은 릴레이가 꺼져 있는지 보지 않아 원인 `16` 보고는 꺼짐의 증거가 아니다. C31은 이 보고만으로도 "꺼졌다가 N초 뒤 켜짐"을 확인한 것으로 보게 했다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 「확정한 결정」·C31, plan.md 검증 전략 C31, tasks.md T033(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- A. 본체 확인 필수: 문장을 실제 관찰로 좁히고, C31에서 꺼졌다가 N초 뒤 켜지는 것을 본체에서, 다시 켤 때의 보고를 로그에서 본다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| --- | --- |
