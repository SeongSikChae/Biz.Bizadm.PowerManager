# D04_28 장비 상태 테스트는 상태 조회 API를 만든 뒤(단계 3)에 한다

## 상황

tasks 검토 1회차 지적 1. plan.md 검증 전략은 `DeviceStateTests`가 상태 조회 API로 C1·C2·C3·C30을 확인한다고 적었다. 그런데 그 API는 단계 3(T014·T017)에서 만들고, tasks.md는 T013을 단계 2에 두고 단계 2 체크포인트에서 통과해야 한다고 적었다. 그대로면 단계 2 체크포인트를 채울 수 없다.

- 정한 단계: tasks
- 관련: 옛 작업 스펙의 tasks.md 단계 2 체크포인트, 단계 3 T013, 의존 관계(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- A. 순서를 옮김: T013을 단계 3의 T017 뒤로 옮기고, 단계 2 체크포인트는 기존 MQTT 테스트 통과만 본다. tasks.md만 고친다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
