# D04_05 B540 스케줄·자동 복구·FOTA 동작은 B540 함수를 디컴파일해 대조한 뒤 관찰로 적는다

## 상황

구현 후 검토 1회차 지적 3. 새 문서 3.1 자동 복구 카운터, 3.3 스케줄 전체, 2절 요약 표의 FOTA·자동 복구·스케줄 근거가 M130-W 디컴파일 결과인데 B540 관찰로 표기됐고, 요약 표 근거 칸이 두 모델 공통이었다. B540은 함수 주소와 문자열 참조만 확인한 상태라 spec C1(표기 규칙)과 C5(모델별 근거 표기)에 어긋났다.

- 정한 단계: 구현
- 관련: 옛 작업 스펙의 mqtt-device-control.md 2절 요약 표(근거 칸 분리), 3.1 자동 복구 항목, 3.2 오브젝트 5, 3.3(`docs/specs/device-control-ref/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_01`

## 결정

- A. B540 디컴파일로 대조: B540 `0x402c9870`(스케줄 해석)·`0x402c9660`(스케줄 저장)·`0x4029b20c`(자동 복구)·`0x402c8f80`(URL 해석)을 디컴파일해 M130-W와 대조한다. 같으면 B540 관찰로 두고 근거 함수 주소를 B540 것으로 바꾸고, 다르면 차이를 적는다. 요약 표 근거 칸을 B540·M130-W로 나눈다.

## 이유

- A는 분석 서버 실행 한 번과 대조만 더하면 되고, B540 제어 구현의 근거가 관찰로 남는다. B는 비용이 조금 작지만 B540 근거가 추정으로 남아 고르지 않았다. 고치지 않음은 C1·C5에 어긋나 고르지 않았다. 대조 결과 네 함수 모두 M130-W와 같은 구조였다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
