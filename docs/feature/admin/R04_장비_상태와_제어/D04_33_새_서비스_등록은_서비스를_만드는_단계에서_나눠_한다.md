# D04_33 새 서비스 등록은 서비스를 만드는 단계에서 나눠 한다

## 상황

plan 검토 6회차 뒤의 tasks 일관성 점검 1. tasks.md T011(단계 2)은 `DeviceStateStore`·`DownlinkDeliveryTracker`·`DeviceRelayReader`·`DeviceStatusService`·`DeviceCommandService`를 `Program.cs`에 등록한다고 적었는데, `DeviceStatusService`(T014)와 `DeviceCommandService`(T016)는 단계 3에서 만든다. 순서대로 하면 없는 클래스를 등록하게 되어 컴파일이 되지 않고 단계 2 체크포인트를 채울 수 없다.

- 정한 단계: tasks
- 관련: 옛 작업 스펙의 tasks.md T011, T014, T016(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- A. 등록을 나눔: T011은 단계 2까지 만든 세 서비스만, T014·T016은 자기 서비스를 만들면서 `Program.cs`에 등록한다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. T011을 단계 3으로 옮김: T011 전체를 T016 뒤로 옮긴다. | 사용자가 말하지 않음 |

## 경위

- 2026-11-22 옛 작업 `docs/specs/device-control/decisions.md`(지움. `15dc357`에 있음) D025에서 옮겼다(2026-11-23).

## 코드

- 옛 기록에 코드 위치가 없다. 짝 태스크 `T04_02`의 「고칠 파일」을 본다.
