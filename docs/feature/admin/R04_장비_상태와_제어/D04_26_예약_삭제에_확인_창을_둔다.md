# D04_26 예약 삭제에 확인 창을 둔다

## 상황

spec 검토 3회차 전체 점검 2. 「확정한 결정」은 확인 창이 있는 동작을 릴레이 끄기·전원 재투입·재부팅으로 적었는데, 장비 제어 화면 조건은 예약 삭제도 확인 창을 거친다고 했다. 예약 삭제 확인 창은 `D04_19`(옛 D011)(삭제를 서버 기록과 상관없이 항상 받음)을 반영하며 에이전트가 더한 것이었고 사용자 결정에 없었다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 「확정한 결정」, C26(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- A. 「확정한 결정」에 더함: 예약 삭제 확인 창을 유지하고 「확정한 결정」에 적는다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 확인 창을 뺌: 예약 삭제는 확인 창 없이 바로 보낸다. | 사용자가 말하지 않음 |

## 경위

- 2026-11-22 옛 작업 `docs/specs/device-control/decisions.md`(지움. `15dc357`에 있음) D018에서 옮겼다(2026-11-23).
