# D04_35 예약의 일요일은 둘째 글자에 2를 더해 보낸다

## 상황

`D04_18`(옛 D010) 대체(요일 문자열을 만드는 방법). `D04_18`(옛 D010)은 요일 7자리를 일~토 순서의 `0`·`1`로 추정해 만들고 실장비에서 확인하기로 했다. 실장비 B540 `1.01.36`에서 2026-11-22(일요일)에 `1000000`(15:36)과 `1111111`(15:40)이 동작하지 않았다. 펌웨어를 다시 분석하니(B540 `1.01.34` `SetLocalAlram` `0x402c9870`, M130-W `2.01.58` `0x4024c0a0`) 요일 순서는 일~토가 맞지만 첫 글자(일요일)의 비트를 합계에 더하지 않아 일요일이 저장되지 않는다. 글자가 `0`·`1`인지 검사하지 않으므로 둘째 글자에 `2`를 넣으면 일요일 비트(`0x40`)가 된다. 같은 장치에서 `0200000`을 시험해 16:00 예약이 동작했다(자동 복구로 다시 켜진 보고, 원인 `16`).

- 정한 단계: 구현
- 관련: 옛 작업 스펙의 spec.md 「근거의 한계」·C12·C31, plan.md 결정(예약 요일), tasks.md 단계 5-1 T038(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- A. 둘째 글자에 더함: 첫 글자는 늘 `0`, 둘째 글자는 월 1과 일 2의 합(`0`~`3`), 나머지는 화~토의 `0`·`1`로 보낸다. 요일 변환 한 곳만 바꾼다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 일요일 선택을 막음: 화면과 서버에서 일요일을 받지 않는다. | 사용자가 말하지 않음 |
| C. 서버가 전원 재투입을 보냄: 서버가 일요일 시각에 전원 재투입을 직접 보낸다. 서버 쪽 예약 실행과 저장이 새로 필요하다. | 사용자가 말하지 않음 |
