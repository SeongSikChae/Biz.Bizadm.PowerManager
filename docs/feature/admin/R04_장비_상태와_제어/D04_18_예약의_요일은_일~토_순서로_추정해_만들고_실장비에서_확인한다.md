# D04_18 예약의 요일은 일~토 순서로 추정해 만들고 실장비에서 확인한다

## 상황

spec 검토 1회차 지적 4. 예약 문자열의 요일 7자리가 어느 요일에 대응하는지 spec에 없었고, 근거 문서 3.3도 대응을 적지 않았다(비트 순서는 추정). 화면에서 고른 요일과 다른 요일에 전원이 끊길 수 있고, 서버 테스트의 기대 페이로드도 정할 수 없었다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md 「근거의 한계」, C12, C26, C31(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- B. 추정 순서로 지원: 첫 자리를 일요일(일~토)로 정하고 추정임을 밝힌다.
- 옛 기록의 결정 칸: B에 실장비 확인을 더함. 추정 순서로 만든 뒤 실장비에서 확인하고, 다르면 고친다.

## 이유

- 사용자가 "B로 만들고 실장비에서 검증을 한 뒤 다르면 수정 조치. 현재 요일 기준으로 현재 시간 기준 몇 분 뒤에 설정해 두고 동작하는지 확인해 보면 검증 가능"이라고 말함. A와 고치지 않음을 고르지 않은 이유는 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.
