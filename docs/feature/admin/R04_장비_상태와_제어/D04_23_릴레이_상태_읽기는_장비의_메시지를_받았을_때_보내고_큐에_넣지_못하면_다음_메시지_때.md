# D04_23 릴레이 상태 읽기는 장비의 메시지를 받았을 때 보내고, 큐에 넣지 못하면 다음 메시지 때 다시 시도한다

## 상황

spec 검토 2회차 지적 2. `D04_17`(옛 D009)로 더한 조건(C30)은 "토픽 정보를 알고, 온라인이고, 릴레이 상태를 모르면 `r` `/100/0/30`을 한 번 보낸다"였다. 재접속 때는 토픽 정보가 이미 있어 접속한 순간 조건이 맞는데, 그 순간 장치는 아직 서버 → 장치 토픽을 구독하지 않았을 수 있고(구독이 없으면 메시지는 아무에게도 가지 않는다. mqtt-broker R13), 보내는 시점과 큐에 넣지 못한 것도 "한 번"으로 치는지가 정해지지 않았다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C30(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- A. 장비의 메시지를 받았을 때: 장비의 메시지를 받았을 때 릴레이 상태를 모르고 이번 접속에서 읽기를 큐에 넣은 적이 없으면 보낸다. 큐에 넣었으면 그 접속 동안 다시 보내지 않고, 넣지 못했으면 다음 장비의 메시지 때 다시 시도한다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| --- | --- |
| B. 장비가 구독할 때: 그 장비 클라이언트가 서버 → 장치 토픽을 구독한 때 보내고, 토픽 정보가 없던 장비는 첫 메시지 때 보낸다. | 사용자가 말하지 않음 |
