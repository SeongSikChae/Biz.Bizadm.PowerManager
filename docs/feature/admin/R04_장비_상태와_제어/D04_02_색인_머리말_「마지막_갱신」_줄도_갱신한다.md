# D04_02 색인 머리말 「마지막 갱신」 줄도 갱신한다

## 상황

spec 검토 2회차 지적 2. `D04_01`(옛 D001)대로 넓힌 C8은 색인(`docs/reference/b540-rea-analysis.md`)에서 링크 한 줄과 제어 관련 문구만 바꾸고 "그 밖의 줄은 바뀌지 않는다"고 했다. 그래서 머리말 「마지막 갱신」 줄(지금 "2026-10-23 (KST), … B540-20 … 실행 여부·결과 대기")도 바꿀 수 없다. 작업이 끝나도 색인은 마지막 갱신을 2026-10-23으로 보여, `D04_01`(옛 D001)이 없애려던 색인 안 불일치(현재 상태와 실제 갱신의 차이)가 머리말에 남는다. 앞서 MQTT 문서 링크를 더할 때도 이 줄은 바꾸지 않았다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md C8(`docs/specs/device-control-ref/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_01`

## 결정

- A. 마지막 갱신 줄도 갱신: C8에 "머리말 「마지막 갱신」 줄은 날짜를 2026-11-21로 바꾸고 제어 기능 근거 문서를 더했다는 짧은 문구를 덧붙이며, B540-20 대기 내용은 그대로 둔다"를 더한다.

## 이유

- A는 비용이 B와 같은 한 문장이고, 색인 현재 상태를 갱신하기로 한 `D04_01`(옛 D001)의 취지와 맞으며, B540-20 대기 내용을 지우지 않아 기존 기록도 보존한다. B는 의도를 드러내지만 날짜 불일치가 남아 고르지 않았다. 고치지 않음은 불일치가 남고 의도도 드러나지 않아 고르지 않았다.
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 바꾸지 않는다고 명시: C8에 "머리말 「마지막 갱신」 줄은 이전 링크 추가 관례대로 바꾸지 않는다"를 더한다. | 위 「이유」에 함께 적힘 |
