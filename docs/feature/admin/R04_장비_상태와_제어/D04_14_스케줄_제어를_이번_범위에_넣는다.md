# D04_14 스케줄 제어를 이번 범위에 넣는다

## 상황

스케줄 제어(`/100/0/58`·`59`)를 이번 작업에 넣을지. 형식이 복잡하고, 장치에서 스케줄 목록을 읽을 수 없어 서버가 보낸 내용을 따로 보관해야 한다.

- 정한 단계: spec
- 관련: 옛 작업 스펙의 spec.md(`docs/specs/device-control/`(지움. `15dc357`에 있음)), 짝 태스크 `T04_02`

## 결정

- A. 이번에 포함: 스케줄 추가·수정·삭제 화면과 기능을 함께 만든다.

## 이유

- 사용자가 말하지 않음
- 옛 결정 기록을 옮긴 것이다. 옛 기록은 사용자가 직접 말한 이유와 에이전트의 추천 이유를 나눠 적지 않았다.

## 버린 안

| 안 | 버린 이유 |
| --- | --- |
| B. 다음 작업으로: 이번에는 릴레이·전원 재투입·재부팅·보고 조건·대기전력 차단만 만든다. | 사용자가 말하지 않음 |

## 경위

- 2026-11-22 옛 작업 `docs/specs/device-control/decisions.md`(지움. `15dc357`에 있음) D006에서 옮겼다(2026-11-23).

## 코드

- 옛 기록에 코드 위치가 없다. 짝 태스크 `T04_02`의 「고칠 파일」을 본다.
