# B540 펌웨어 정적 분석 결과

분석 대상은 B540 플래시 덤프 두 사본이다. 두 사본은 각각 1,048,576바이트이며 SHA-256이 같아 동일한 덤프의 복사본으로 확인됐다. 펌웨어는 실행하지 않았다.

## 확인된 이미지 구조

- ESP8266 계열 Xtensa 이미지 구조다. 부트 이미지 헤더는 E9이고 진입 주소는 `0x40100438`이다.
- 부트 이미지 헤더의 플래시 크기/속도 값은 `0x20`으로, ESP8266 헤더 표기상 1 MiB / 40 MHz에 해당한다.
- 부트로더 문자열과 이미지 메타데이터는 512 KiB씩 나뉜 두 슬롯, 백업 부팅, 부팅 실패 시 다른 슬롯 시도 구조를 가리킨다.
- 앱 슬롯 A는 `0x1000`, 슬롯 B는 `0x81000`에서 시작한다. 각 슬롯은 EA OTA v2 컨테이너, IROM 영역, 내부 E9 RAM 이미지로 구성된다. 두 컨테이너 간격은 `0x80000`이다.
- 슬롯 A IROM은 파일 오프셋 `0x1010–0x56080`(348,272바이트), 슬롯 B IROM은 `0x81010–0xd61a0`(348,560바이트)다.
- 두 슬롯 모두 내부 이미지 체크섬과 컨테이너 CRC가 맞는다. 각 내부 E9 이미지 버전 문자열은 `2.0.0(656edbf)`로 일치한다.
- 구간·해시 정보 JSON에는 슬롯별 구간, 주소, 해시, 체크섬 결과가 기록되어 있다. 전체 IROM과 RAM 구간을 포함한 Ghidra 프로젝트도 만들었다(둘 다 저장소에 없는 로컬 산출물).

## 펌웨어가 드러내는 제품 동작

문자열과 참조 테이블에서 다음 기능과 프로토콜 이름을 확인했다.

- 제품 식별자 형식: `DWD-LS120_%02x%02x%02x`
- 릴레이 켜기/끄기, 버튼 켜기/끄기 이벤트
- 공장 검사 항목: 시작, ON/OFF 명령, `Measurement`, `OverLoad`
- 장치와 PC 사이의 명령 이름: `SCAN_AP`, `ON_CMD`, `OFF_CMD`; 슬롯 B에는 `FACTORY_RESET`도 존재
- Wi‑Fi 설정, MQTT 연결/읽기/쓰기/실행, TLS 설정, 장치 등록 HTTP API, 별도 OTA 설정 키

이 목록은 펌웨어의 문자열·테이블에서 읽은 기능 명칭이다. 특히 `DUT<>PC` 표기가 실제 UART 물리 연결임을 단정할 만한 GPIO/API 코드 경로는 아직 확인하지 못했다.

## 슬롯 차이

슬롯 A와 B는 같은 버전 문자열을 사용하지만 코드/데이터 일부가 다르다. 슬롯 B에는 `FACTORY_RESET` 명령과 `FactoryTestFactoryReset` 문자열이 추가되어 있어, 두 슬롯이 완전히 같은 앱 바이너리는 아니다. 슬롯 B를 현행 또는 정식 버전이라고 판단할 증거는 없다.

## ESPHome 제작에 아직 필요한 정보

현재 펌웨어로 ESP8266 기반이라는 점과 기본 제품 기능은 파악했지만, 재현 가능한 ESPHome 빌드에 필수적인 보드 연결 정보는 확정되지 않았다.

- 릴레이 제어 GPIO, 출력 논리(활성 HIGH/LOW), 부팅 시 안전 상태
- 버튼 GPIO와 풀업/풀다운 방식
- 과전류/전력 측정 IC 종류와 연결 핀 또는 보조 MCU 통신 방식
- 보드의 정확한 리비전 및 플래시/모듈 확인

그래서 현 시점에서 실제 핀 번호를 임의로 넣은 YAML은 만들지 않았다. 다음 단계는 IROM 코드의 함수 경계를 더 정밀하게 복구해 GPIO/직렬 주변장치 접근을 찾고, 가능하면 보드 사진·PCB 표기 또는 회로 정보를 대조하는 것이다. 측정 IC나 보조 MCU 연결을 확인해야 `Measurement`와 `OverLoad` 동작을 ESPHome 쪽에서 재현할 수 있다.

## 분석 산출물

아래는 분석 중 만든 로컬 산출물이며 저장소에는 없다.

- 구간·해시 정보 JSON: 이미지 구간, 해시, 검증값
- 슬롯별 IROM 추출본(슬롯 A·B): 앱 플래시 코드 구간 추출본
- 문자열·참조 요약 텍스트(슬롯 A·B): 문자열과 참조 요약
- Ghidra 디컴파일 출력(슬롯 A·B): Ghidra 디컴파일 출력
- RAM 데이터 참조 목록(슬롯 A): RAM 데이터 참조 목록
- Ghidra 프로젝트: IROM/RAM 구간을 Xtensa little-endian으로 불러온 Ghidra 프로젝트
