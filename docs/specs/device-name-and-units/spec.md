# 장비명·입력 단위 표기·제어 화면 로딩 개선

## 무엇을, 왜

세 가지를 함께 고친다. 모두 #28의 대시보드·장비 제어 화면 위에서 고친다.

- **로딩(#33)**: 장비 제어 화면은 들어갈 때마다 설정을 다시 읽고, 읽는 동안 설정 묶음 셋을 통째로 회색 상자 둘로 바꾼다(`src/Biz.Bizadm.PowerManager.Client/src/features/device-control/DeviceControlPage.tsx`의 `SettingsSections`·`LoadSkeleton`). 값이 없어도 그릴 수 있는 제목·입력 칸·버튼까지 응답을 기다리고, 2열에서는 쌓인 회색 상자에 맞춰 "전원" 묶음이 400px로 늘었다 268px로 줄어(1440px, 헤드리스 Edge에서 측정) 느려 보인다. 묶음의 틀을 응답과 관계없이 바로 그린다(D001).
- **단위·범위(#31)**: 설정 입력에 단위가 거의 없고, 넣을 수 있는 범위는 잘못 넣고 저장해야 오류로만 보인다. 단위는 입력 이름에, 뜻과 범위는 입력 아래에 늘 보인다(D005). 추정한 단위는 장비 모델에 맞춰 "추정"을 붙인다(D006).
- **장비명(#32)**: 장비를 모델과 MAC으로만 구분해야 한다. 사용자가 정한 장비명을 서버가 보관하고 화면에 보인다. 장비명은 장비 제어 화면 머리에서 정하고(D002), 같은 이름을 여러 장비에 쓸 수 있으며(D003), 대시보드 카드는 장비명 순서로 보인다(D004).

단위의 근거(제어 값의 의미는 `docs/reference/mqtt-device-control.md` 3.1~3.4와 `docs/reference/b540-mqtt-topic.md` 「오브젝트 99 리소스 처리」를 따른다):

- 최소·최대 간격: B540 `1.01.36` 실장비 한 대에 보고 조건 `5`/`30`/`1`을 보낸 뒤(2026-11-22 16:48:49) 같은 장비의 상태 보고(`sid` `1`) 간격이 5.22~5.28초(202회)와 30.72~31.13초(136회)에 모였고, 그 밖의 27회 가운데 23회는 약 10.4·15.5·20.7·25.7초였다(운영 서버 로그, 2026-11-22 16:48:50~21:05 가운데 서버가 실행 중이던 때). 그 보고들의 `/99/0/5` 값은 간격 순서대로 `5`, `30`, `10`·`15`·`20`·`25`였다(나머지 4회는 서버를 멈췄거나 첫 간격). 그래서 한 단위는 약 1초(약 1.02~1.06초)로 확인한 것으로 본다. M130-W는 값을 바꿔 확인한 적이 없다.
- 변화 기준: 펌웨어 로그 이름 `CheckPer`에서 %로 추정한다.
- 기준 전력: B540 `1.01.34` 코드는 이 값을 전력(리소스 11)과 같은 저장 배율로 비교하므로(근거 문서 3.2) W로 추정한다. 실장비 B540 `1.01.36`에 `1.00`을 보내자 `1.10`으로 응답해 배율은 미확인이다.
- 지연: 실장비 B540 `1.01.36`에 `1`을 보낸 뒤, 다시 켜진 보고에서 차단 보고까지 약 2.0초와 약 1.9초였고(운영 서버 로그, 2026-11-22 16:43:34~36, 16:48:31~33) 값 하나만 보았으므로 초로 추정한다.
- 전원 재투입: B540 `1.01.36`에서 한 단위가 약 1초임을 확인했다(근거 문서 3.1). 예약의 "다시 켤 때까지의 초"는 코드로 초 단위를 추정했고 B540 `1.01.36`에서 값 10의 동작만 보았으므로 추정이다(근거 문서 3.3). 둘 다 M130-W는 미확인이다.

확정한 결정:

- 설정 값은 지금처럼 화면에 들어갈 때마다 서버에서 새로 읽는다. 읽기 전에는 입력할 수 없으므로, 작성 중인 값이 응답으로 덮이는 일은 없다.
- 예약 "삭제"는 설정 값과 무관하므로(device-control R13·R18) 설정을 읽는 중이거나 읽지 못해도 누를 수 있다.
- 장비명의 길이는 UTF-16 코드 단위로 센다(이모지는 2 이상으로 센다).
- 장비명 순서는 한국어 순서 규칙으로 비교하고, 이름 안의 숫자는 수로 비교한다("거실 2"가 "거실 10"보다 앞).
- 관리 화면에는 인증이 없다(admin-ui 기준 spec 머리말). 새 관리 API도 관리 포트 제한(admin-ui R6)만 둔다.

범위 밖:

- 원격 데스크톱 연결 중 서버의 설정 조회가 2~3초 걸렸던 원인의 조사와 개선(원인 미확정)
- 설정 값의 DB 보관과 장치에서 읽기(#29), 스케줄·타이머(#30)
- 서버가 받는 입력 범위의 변경, 장비명을 장치에 보내는 것
- 장비 목록 화면에서의 장비명 수정, 장비명 열 정렬
- 대시보드와 장비 목록의 로딩 표시, 장비 제어 화면이 상태를 아직 받지 못했을 때의 스켈레톤

## 완료 조건

용어: **mac**은 소문자 12자리 16진수다. **관리 포트**는 `HttpPort`·`HttpsPort`, **장치 포트**는 `DeviceHttpPort`·`DeviceHttpsPort`다. **설정 묶음**은 장비 제어 화면의 "보고 조건"·"대기전력 차단"·"예약 전원 재투입"이다. **B540 장비**는 `modelId`가 `B540`으로 시작하는 장비다.

로딩(#33):

- C1. 장비 상태를 받은 장비 제어 화면은 설정 응답이 오기 전에도 네 묶음의 제목·안내·입력·버튼을 모두 보인다. 응답 전에는 설정 묶음의 입력(글자 입력, 사용 스위치, 요일)과 "저장"이 비활성이고, 입력은 비어 있으며, 버튼 줄에 "설정을 불러오는 중" 안내(`role="status"`)가 있다. 예약 "삭제"와 "전원" 묶음은 설정 응답과 관계없이 device-control R17·R18대로 쓸 수 있다.
- C2. 설정 응답이 오면 같은 묶음에 값을 채우고(device-control R18) 입력을 활성으로 바꾸며 "설정을 불러오는 중" 안내를 없앤다. "저장"은 제어 가능한 장비면 활성이 된다. 응답 전과 후에 네 묶음의 위치와 크기가 같다(1440px 2열, 800px 1열, 390px 1열). 이 화면의 설정 묶음에는 스켈레톤을 쓰지 않는다.
- C3. 설정 조회가 실패하면 묶음을 그대로 두고 묶음들 위에 "설정을 불러오지 못했습니다" 오류 안내(원인, "다시 시도")를 보인다. 설정 묶음의 입력과 "저장"은 비활성으로 남고 "설정을 불러오는 중" 안내는 없다. "다시 시도"를 누르면 다시 읽는 동안 오류 안내를 둔 채 "다시 시도"를 비활성으로 하고 C1의 "설정을 불러오는 중" 안내를 보이며, 성공하면 오류 안내를 없애고 C2대로 채운다.
- C4. 설정 조회가 끝나기 전에 예약을 삭제해 성공하면 "장비에 보냈습니다" 안내를 보이고, 그 뒤 온 설정 응답이 삭제 전의 예약을 담고 있어도 예약 입력은 비운 채로 둔다.

장비명(#32):

- C10. 장비명을 장비마다 DB에 저장한다(없으면 빈 문자열). 시작 시 마이그레이션이 적용되고, 기존 DB의 장비는 값을 잃지 않은 채 장비명이 빈 문자열이 된다.
- C11. 관리 포트의 `PUT /api/admin/devices/{mac}/name`은 본문 `{"name":"<장비명>"}`의 앞뒤 공백(.NET `char.IsWhiteSpace`가 참인 문자)을 먼저 없애고, 없앤 값을 검사해 저장하고 204를 반환한다. 없앤 값이 빈 문자열이면 장비명을 지운다. 실패는 ProblemDetails이고 저장하지 않으며, 판정 순서는 mac 형식(400) → 등록(404) → 장비명(400)이다. 장비명이 없거나 null이거나, 없앤 값의 길이가 30을 넘거나, 없앤 값에 제어 문자·줄 구분 문자(U+2028·U+2029 포함)가 들어 있으면 400이다(`"거실\n"`은 "거실"로 저장, `"\t"`는 이름 삭제, `"거\n실"`은 400). 장치 포트에서는 404 ProblemDetails이고 저장하지 않는다.
- C12. 장치가 다시 등록 요청(`register`)을 보내도 장비명은 바뀌지 않는다. 장비명을 바꿔도 device-register R5의 다른 값(마지막 요청 시각 포함)과 장치 응답은 바뀌지 않는다.
- C13. 장비 목록 API(device-list R1), 상태 조회 API와 상태 스트림(device-control R5·R6)의 원소에 `name`(장비명, 없으면 빈 문자열)이 있다. 장비명이 바뀌면 상태 스트림이 그 장비의 원소를 보내고, 같은 값으로 저장하면 보내지 않는다.
- C14. 장비 제어 화면 머리에는 장비명이 있으면 제목(`h1`)에 장비명, 그 아래에 모델과 mac을, 없으면 지금처럼 제목에 모델, 그 아래에 mac을 보인다. 제목 옆에 "이름 변경" 버튼이 있고 장비가 오프라인이어도 누를 수 있다.
- C15. "이름 변경"은 장비(모델·mac)를 밝힌 창을 열고, 지금 장비명이 채워진 입력(이름 "장비 이름", 설명 "30자까지. 비워서 저장하면 이름을 지웁니다")과 "취소"·"저장"을 보인다. "취소"·Esc는 아무것도 보내지 않고 닫는다. 입력의 앞뒤 공백을 C11과 같은 문자로 없앤 값의 길이와 문자가 C11에 어긋나면 보내지 않고 입력 옆에 이유를 보인다. 저장하는 동안 "저장"은 비활성이다. 성공하면 창을 닫고 머리의 이름이 새 이름으로 바뀌며(스트림이 끊겨 있어도), 실패하면 창을 열어 둔 채 원인을 보인다.
- C16. 대시보드 카드는 장비명이 있으면 제목에 장비명, 그 아래에 모델과 mac을, 없으면 지금처럼 제목에 모델, 그 아래에 mac을 보인다. 확인 창은 장비명이 있으면 `장비명 — 모델 (mac)`, 없으면 지금처럼 `모델 (mac)`으로 장비를 밝힌다. mac은 확인 창과 이름 변경 창을 포함해 고정폭이다.
- C17. 대시보드 카드는 장비명이 있는 장비를 장비명 오름차순(같으면 mac 오름차순)으로 먼저, 장비명이 없는 장비를 mac 오름차순으로 뒤에 보인다. 장비명이 바뀌면 새로 고침 없이 이름과 순서에 반영한다.
- C18. 장비 목록 표는 "이름" 열을 맨 앞에 두고(빈 값은 "—") 나머지 열의 순서는 그대로다. 검색은 장비명도 대소문자 구분 없이 부분 일치로 거르고, 검색 입력의 자리 표시글은 "이름, MAC, 모델, 사용자로 검색"이다. 장비명을 바꾼 뒤 장비 목록을 열면 바뀐 이름이 보인다.
- C19. 공백 없는 30자 장비명이어도 폭 390px의 대시보드·장비 제어 화면·확인 창·이름 변경 창에서 내용이 밖으로 넘치지 않고 페이지 가로 스크롤이 생기지 않는다.
