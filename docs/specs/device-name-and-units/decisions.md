# 장비명·입력 단위 표기·제어 화면 로딩 개선 결정

### D001 설정 응답을 기다리는 동안 묶음의 틀을 바로 그린다
- 단계: spec
- 질문: 장비 제어 화면에 들어가 설정 응답을 기다리는 동안 설정 묶음 셋(보고 조건·대기전력 차단·예약 전원 재투입)을 어떻게 보일지. 지금은 셋을 회색 상자 둘로 통째로 바꿔 응답이 늦으면 화면이 멈춘 것처럼 보이고, 2열에서는 "전원" 묶음이 400px로 늘었다 268px로 줄어든다(1440px에서 측정).
- 선택지:
  - A. 틀을 바로 그림: 제목·안내·입력 칸·버튼을 바로 그리고 입력과 저장만 비활성으로 둔다. 값이 오면 채우고 활성으로 바꾼다. 회색 상자와 깜박임을 없앤다. 예약 "삭제"는 설정 값과 무관하므로 응답 전에도 제어 가능하면 누를 수 있다.
  - B. 회색 상자를 실제 배치로: 회색 상자를 셋으로 늘려 실제 묶음과 같은 자리·높이에 두고 깜박임을 없앤다. 응답이 올 때까지 내용은 보이지 않는다.
  - C. 앞서 받은 값 먼저: 이전에 받은 설정을 남겨 바로 보인 뒤 뒤에서 새로 읽는다. 처음 들어갈 때는 A처럼 틀을 바로 그린다.
- 결정: A
- 이유: 사용자가 말하지 않음
- 반영: spec.md

### D002 장비명은 장비 제어 화면 머리에서 정한다
- 단계: spec
- 질문: 장비명을 어디에서 입력·수정·삭제할지. 장비에는 지금 이름이 없어 모델과 MAC으로만 구분한다.
- 선택지:
  - A. 장비 제어 화면 머리: 머리의 이름 옆 "이름 변경" 버튼으로 창을 열어 저장하고, 비워서 저장하면 이름을 지운다. 장비가 오프라인이어도 할 수 있다.
  - B. 장비 목록: 장비 목록 표에 "이름" 열과 행마다 수정 버튼을 두고 같은 창으로 저장한다.
  - C. 둘 다: A와 B의 두 자리에서 모두 고친다.
- 결정: A
- 이유: 사용자가 말하지 않음
- 반영: spec.md

### D003 같은 장비명을 여러 장비에 쓸 수 있다
- 단계: spec
- 질문: 장비명의 규칙. 앞뒤 공백을 없앤 뒤 1~30자, 줄바꿈·제어 문자는 받지 않는 것은 공통이고, 같은 이름을 두 장비에 쓸 수 있는지를 정한다.
- 선택지:
  - A. 중복 허용: 같은 이름을 여러 장비에 쓸 수 있고, 화면에는 이름과 함께 모델·MAC을 보여 구분한다.
  - B. 중복 금지: 다른 장비가 쓰는 이름(대소문자 무시)이면 409로 거부하고 입력 옆에 이유를 보이며 DB에 유일 조건을 둔다.
- 결정: A
- 이유: 사용자가 말하지 않음
- 반영: spec.md

### D004 대시보드 카드는 장비명 순서로 보인다
- 단계: spec
- 질문: 대시보드 카드 순서에 장비명을 쓸지. 지금은 MAC 오름차순이다. 장비 목록의 기본 정렬은 그대로 두고 검색에 이름을 더하는 것을 전제로 했다.
- 선택지:
  - A. 이름순, 없으면 뒤: 이름이 있는 장비를 이름 가나다순으로 먼저, 이름 없는 장비를 MAC 순으로 뒤에 보인다. 이름이 같으면 MAC 순이다.
  - B. 지금처럼 MAC 순: 이름과 관계없이 MAC 오름차순을 유지한다.
- 결정: A
- 이유: 사용자가 말하지 않음
- 반영: spec.md

### D005 단위는 입력 이름에, 뜻과 범위는 입력 아래에 보인다
- 단계: spec
- 질문: 입력마다 단위와 넣을 수 있는 범위를 어떤 모양으로 보일지. 지금은 단위가 거의 없고 범위는 잘못 넣고 저장해야 오류로만 보인다.
- 선택지:
  - A. 이름에 단위, 아래 설명: 입력 이름 뒤에 괄호로 단위를 적고, 입력 아래 작은 글자로 뜻과 범위를 항상 보인다. 오류가 있으면 설명 아래에 더 보인다.
  - B. 입력 칸 안에 단위: 입력 칸 오른쪽 끝에 단위를 붙이고 범위는 빈 칸의 자리 표시글로 보인다. 값을 넣으면 범위가 사라진다. 뜻 설명은 묶음 안내에 모은다.
  - C. 도움말 아이콘: 단위는 이름에 적고 뜻과 범위는 이름 옆 아이콘을 눌러 본다.
- 결정: A
- 이유: 사용자가 말하지 않음
- 반영: spec.md

### D006 추정한 단위는 장비 모델에 맞춰 "추정"을 붙인다
- 단계: spec
- 질문: 확인한 단위와 추정한 단위를 어떻게 구분해 보일지. B540 `1.01.36` 실장비에서 보고 조건 5/30/1을 보낸 뒤 보고 간격이 5.22~5.28초(202회)와 30.72~31.13초(136회)에 모여(서버 로그, 2026-11-22) 최소·최대 간격은 약 1초 단위로 확인했다. 변화 기준 %, 기준 전력 W, 지연 초는 추정이고, M130-W는 값을 바꿔 확인한 적이 없다.
- 선택지:
  - A. 장비 모델에 맞춰: 확인한 단위는 단위만, 추정은 단위 뒤에 "추정"을 붙인다. B540이 아닌 모델에서는 모든 단위를 추정으로 보인다(예약의 시·분·초는 이름 자체가 단위라 그대로). 묶음 안내의 "값의 의미와 단위는 추정입니다"와 "전원 재투입 단위는 약 1초입니다(B540에서 확인)"는 뺀다.
  - B. 모델과 관계없이 같게: 모든 모델에서 같은 문구를 쓰고, B540에서만 확인한 값은 "B540에서 확인"이라고 설명에 적는다.
  - C. 추정은 단위를 안 적음: 확인한 단위만 적고, 추정인 값은 단위 없이 "단위 미확인"이라고만 적는다.
- 결정: A
- 이유: 사용자가 말하지 않음
- 반영: spec.md

### D007 최소·최대 간격의 설명은 "계량 값"으로 쓰고 다른 모델은 추정으로 쓴다
- 단계: spec
- 질문: spec 검토 1회차 지적 2. C6의 최소·최대 간격 설명이 모델과 관계없이 단정이었다. M130-W는 보고 조건의 의미가 추정이고(`docs/reference/mqtt-device-control.md` 2절), B540에서 본 것도 `sid` `1` 보고의 간격뿐이며 릴레이 변경은 `sid` `2`로 따로 보고되는데(3.4) "값이 바뀌어도 이 시간 안에는 다시 보고하지 않습니다"라고 했다. 다른 모델에서 이름과 설명이 어긋나고 릴레이 표시도 늦어진다고 오해할 수 있다.
- 선택지:
  - A. 계량 값, 모델별 문구: "값"을 "계량 값"으로 바꾸고 B540이 아니면 "…것으로 추정합니다"를 쓴다. 변화 기준도 "계량 값이 이만큼 바뀌면 …"으로 맞춘다.
  - B. 계량 값으로만 바꿈: 모델 구분은 이름의 "추정"에 맡기고 설명은 모든 모델이 같다.
  - 고치지 않음: 지금 설명을 그대로 쓴다.
- 결정: A
- 이유: 사용자가 말하지 않음
- 반영: spec.md C6

### D008 장비명은 앞뒤 공백을 없앤 뒤 검사한다
- 단계: spec
- 질문: spec 검토 1회차 지적 3. C11과 C15에서 제어 문자·줄 구분 문자를 공백을 없애기 전에 보는지 뒤에 보는지, 공백이 무엇인지 정하지 않았다. `"거실\n"`과 `"\t"`의 결과가 갈리고, JS `trim`과 .NET `Trim`이 U+FEFF·U+0085에서 달라 화면과 서버 판정이 갈릴 수 있었다.
- 선택지:
  - A. 공백을 없앤 뒤 검사: 앞뒤 공백(.NET `char.IsWhiteSpace`가 참인 문자)을 먼저 없애고 그 값으로 길이와 문자를 검사하며, 화면도 같은 문자를 없앤다. `"거실\n"`은 저장, `"\t"`는 이름 삭제, `"거\n실"`은 400이다.
  - B. 검사한 뒤 공백 제거: 제어·줄 구분 문자는 앞뒤에 있어도 거부하고 그 뒤 공백을 없애 길이를 검사한다.
  - 고치지 않음: 검사 순서와 공백의 범위를 정하지 않는다.
- 결정: A
- 이유: 사용자가 말하지 않음
- 반영: spec.md C11, C15

### D010 성공 안내가 보이는 동안 "설정을 불러오는 중"은 화면에서만 숨긴다
- 단계: plan
- 질문: plan 검토 1회차 지적 1. 폭 390px에서 설정 응답 전에 예약 삭제가 성공하면 버튼 줄에 "저장", "삭제", "장비에 보냈습니다", "설정을 불러오는 중"이 함께 놓여(약 336px, 쓸 수 있는 폭 310px) 줄이 바뀌고, 예약 묶음 높이가 28px 늘었다가 응답 뒤 줄어든다. spec C2와 device-control R21에 어긋난다.
- 선택지:
  - A. 하나만 보이게 함: 성공 안내가 보이는 동안 "설정을 불러오는 중"을 화면에서만 숨긴다(`sr-only`, 읽기 프로그램에는 남음).
  - B. 성공 안내를 버튼 줄 위로: 성공 안내를 실패 안내처럼 버튼 줄 위에 보인다.
  - 고치지 않음: 두 안내가 함께 보일 수 있다.
- 결정: A
- 이유: 사용자가 말하지 않음
- 반영: plan.md 인터페이스·데이터, 검증 전략

### D011 장비명 저장의 성공은 그 폼이 화면에 있을 때만 창을 닫는다
- 단계: 구현
- 질문: 구현 후 검토 1회차 지적 1. 장비명을 저장하는 동안 "취소"나 Esc로 닫고 "이름 변경"을 다시 열면, 앞 요청이 성공한 순간 다시 연 창이 닫히고 쓰던 이름이 안내 없이 사라졌다. 앞 폼이 사라진 뒤에도 `onSaved`가 부모의 창을 닫기 때문이다. 응답이 늦을 때 입력을 잃는다.
- 선택지:
  - A. 폼이 있을 때만 닫음: 저장을 보낸 폼이 아직 화면에 있을 때만 성공 뒤 창을 닫는다.
  - B. 보내는 동안 닫지 못함: 저장 응답이 올 때까지 "취소"와 Esc를 막는다.
  - 고치지 않음: 앞 저장의 성공이 지금 열린 창을 닫는다.
- 결정: A
- 이유: 사용자가 말하지 않음
- 반영: DeviceNameDialog.tsx
