# 장비 목록 화면

기능: device-list(새 기능) / admin-ui(새 기능)
이슈: GitHub #17

## 무엇을, 왜

관리 화면(`Biz.Bizadm.PowerManager.Client`)은 shadcn(`radix-nova` 스타일, `neutral` 기본색) + Tailwind 4 + Redux Toolkit 골격만 있고, 화면은 `App.tsx`의 제목 한 줄뿐이다. 서버에 등록된 장비(`DeviceRegistration`)를 볼 방법이 없다. 서버에 등록된 장비를 보는 첫 화면으로 장비 목록을 만든다.

관리 화면의 디자인이 정해져 있지 않았으므로 시안을 만들어 확정했다(2026-11-19, 테이블안). 시안: https://claude.ai/artifact/LQMfPZ4gsT4t5kJYuKMBPU 의 "A. 테이블안". 이 화면이 관리 화면의 첫 화면이므로 앱 틀(사이드바 + 본문)과 디자인 기준을 함께 정해 이후 화면이 따르게 한다.

확정한 결정:

- 목록 형태는 테이블이다.
- MAC은 원본 그대로(소문자 12자리 16진수) 표기한다.
- 테마는 클라이언트 `src/index.css`의 shadcn 토큰(라이트)을 그대로 쓴다. 새 디자인 시스템이나 UI 라이브러리를 들이지 않는다.
- 서버는 관리 포트(`HttpPort`·`HttpsPort`)와 장치 포트(`DeviceHttpPort`·`DeviceHttpsPort`)가 같은 컨트롤러를 받는다. 목록 API는 인증이 없으므로 장치 포트에서는 응답하지 않는다. 인증은 별도 이슈로 하며, 그 전까지 관리 포트를 외부에 노출하지 않는 운영을 전제로 한다.

시안과 달라지는 점(이번 범위에서 뺌):

- 온라인/오프라인 상태 열과 상태별 거르기: 서버가 연결 상태를 저장하지 않으므로 뺀다(#14, #15 뒤 별도 일감).
- 모델 필터 드롭다운: 검색이 모델명도 찾으므로 뺀다.
- 사이드바의 펌웨어(FOTA)·설정 항목: 화면이 없으므로 넣지 않는다.

범위 밖:

- 인증·권한(별도 이슈)
- 연결 상태·측정값 저장과 표시, 장비 상세·제어 화면
- 다크 모드, 모바일 전용 목록 형태(시안의 모바일 화면)
- 서버 쪽 페이지 나누기·검색

## 완료 조건

서버(장비 목록 API):

관리 포트는 `HttpPort`·`HttpsPort`, 장치 포트는 `DeviceHttpPort`·`DeviceHttpsPort`다(TLS 사용 여부와 무관). TLS를 쓸 때 HTTP 포트로 온 요청을 HTTPS 포트로 리다이렉트하는 기존 동작(`HttpsPortRedirectionMiddleware`)은 그대로 두며, C1·C3은 리다이렉트되지 않고 그 포트에서 처리되는 요청에 대한 것이다.

- C1. 관리 포트로 장비 목록 API를 `GET` 하면 200과 `application/json` 배열을 반환한다. 원소의 필드는 `mac`, `userId`, `modelId`, `company`, `registeredAt`, `lastRequestedAt` 여섯 개뿐이며, 시각은 오프셋이 붙은 ISO 8601 문자열이다. MQTT 키는 어떤 이름으로도 응답에 없다.
- C2. 배열은 저장된 장비 전체이며 `lastRequestedAt`이 최근인 순서다(같으면 `mac` 오름차순). 등록된 장비가 없으면 빈 배열을 반환한다.
- C3. 장치 포트(HTTP·HTTPS 모두)에서 처리되는 장비 목록 API 요청은 404 ProblemDetails를 반환하고 장비 정보를 내주지 않는다. 기존 장치 endpoint(register·connect)의 동작은 두 포트 모두에서 바뀌지 않는다.

클라이언트(장비 목록 화면):

- C4. 관리 화면을 열면(`/`) 왼쪽에 사이드바(제품명 "PowerManager"와 "장비" 메뉴, 현재 메뉴 강조)와 오른쪽 본문으로 된 앱 틀 안에 장비 목록이 나온다. 본문 머리에는 제목 "장비", 등록 대수("서버에 등록된 장비 N대"), "새로고침" 버튼이 있다. N은 검색과 관계없이 서버가 준 전체 대수이며, 받은 목록이 아직 없을 때(C10)는 등록 대수 문구를 표시하지 않는다.
- C5. 표의 열은 MAC, 모델, 제조사, 사용자, 등록, 마지막 요청 순서다. MAC은 고정폭 글꼴로 서버 값 그대로(소문자 12자리) 표시한다. 빈 값(모델·제조사·사용자)은 "—"로 표시한다.
- C6. 등록·마지막 요청 시각은 브라우저 시간대의 `YYYY-MM-DD HH:mm`으로 표시한다. 마지막 요청은 그 위에 상대 시간을 함께 표시한다. 상대 시간은 브라우저 현재 시각과의 차이로 정하며, 1분 미만이거나 미래 시각이면 "방금", 60분 미만이면 "N분 전", 24시간 미만이면 "N시간 전", 그 이상이면 "N일 전"이다(N은 내림).
- C7. 기본 정렬은 마지막 요청 최근 순이다. 등록·마지막 요청 열 머리를 누르면 그 열의 최근 순(내림차순)으로 정렬하고, 같은 열을 다시 누르면 방향이 바뀐다. 값이 같은 행은 MAC 오름차순이다. 정렬 중인 열과 방향이 표시된다(`aria-sort` 포함).
- C8. 검색 입력으로 MAC·모델·사용자를 대소문자 구분 없이 부분 일치로 거른다. MAC 검색은 콜론(`:`)·하이픈(`-`)을 무시한다. 결과가 없으면 "검색 결과 없음" 상태와 "검색어 지우기" 버튼을 보인다.
- C9. 한 페이지에 50대까지 보이고, 넘으면 이전·다음 페이지 버튼과 "현재 / 전체 페이지"를 보인다. 검색어나 정렬이 바뀌면 첫 페이지로 돌아간다.
- C10. 화면은 서버에서 받은 목록이 있는지(빈 목록 포함)로 정한다. "새로고침"과 "다시 시도"는 목록을 다시 불러온다. 받은 목록이 있으면 그 목록이 비었을 때 빈 목록 안내("등록된 장비가 없습니다")를, 아니면 표를 보인다.
  - 받은 목록이 아직 없을 때(처음 불러올 때, 처음 조회에 실패한 뒤 다시 시도할 때): 불러오는 동안 행 모양 스켈레톤을 보이고, 실패하면 목록 자리에 오류 안내와 "다시 시도" 버튼을 보인다.
  - 받은 목록이 있을 때: 다시 불러오는 동안 기존 화면(표 또는 빈 목록 안내)과 등록 대수, 이미 떠 있는 오류 안내를 그대로 두고 "새로고침"·"다시 시도" 버튼을 비활성화한다. 실패하면 기존 화면·검색어·정렬·페이지를 그대로 두고 그 위에 오류 안내와 "다시 시도" 버튼을 보인다. 성공하면 오류 안내를 없애고 새 목록을 보이며, 검색어·정렬·현재 페이지를 유지한다(현재 페이지가 전체 페이지 수를 넘으면 마지막 페이지로 간다).
- C11. 폭 1440px에서는 사이드바와 본문이 나란히 놓인다. 폭 390px에서는 사이드바가 본문 위로 쌓이고, 표는 테두리 상자 안에서 가로로 스크롤되며 페이지 전체에는 가로 스크롤이 생기지 않는다.
- C12. 한글이 Geist 다음 대체 글꼴로 지정한 한글 웹 글꼴로 표시된다(사용자 PC에 설치된 글꼴에 의존하지 않음).
- C13. 접근성: 검색 입력에 레이블이 있고, 아이콘만 있는 버튼에 `aria-label`이 있으며, 모든 조작을 키보드로 할 수 있고 포커스 표시가 보인다.

디자인 기준·검증:

- C14. 기준 spec 두 개가 있다. `docs/features/device-list.md`에는 장비 목록 API와 화면 요구(C1~C13)가, `docs/features/admin-ui.md`에는 관리 화면 디자인 기준(테마 토큰 출처, 글꼴, 앱 틀 구조, 표·버튼·상태 화면 규칙, 시안 링크)이 요구로 적혀 있다.
- C15. C1~C3을 확인하는 서버 자동 테스트와, C4~C10·C13을 확인하는 클라이언트 자동 테스트(Vitest)가 있고 통과한다. 클라이언트 `npm run build`와 `npm run lint`가 통과한다.
- C16. 개발 서버로 실제 화면을 띄워 C4~C13을 브라우저에서 확인하고(폭 1440px와 390px, 키보드 조작과 포커스 표시 포함), 확인 결과를 작업 문서에 기록한다.
