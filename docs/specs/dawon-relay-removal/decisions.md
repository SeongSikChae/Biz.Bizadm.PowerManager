# 다원 중계 모드 제거 결정

### D001 설정 파일에 남은 `DawonRelay` 섹션은 따로 받아 주지 않는다
- 단계: spec
- 질문: 중계 모드를 제거하면 `AppConfiguration.DawonRelay` 속성도 사라진다. 서버는 설정 YAML을 기본 YamlDotNet `Deserializer`로 읽으므로 모르는 키가 있으면 예외가 나고 "Configuration error"와 종료 코드 2로 시작하지 않는다. 또 시작할 때 비밀 값을 암호화하며 설정 파일을 직렬화해 다시 쓰는데, #20 이후 코드가 다시 쓴 파일에는 중계를 켠 적이 없어도 `DawonRelay:` 줄이 들어 있을 수 있다. 남은 섹션을 어떻게 처리할지 정해야 했다.
- 선택지:
  - A. 그냥 제거: `DawonRelay` 속성을 지운다. 남은 섹션이 있으면 시작할 때 키 이름이 담긴 설정 오류(종료 코드 2)로 끝나며, 사용자가 그 줄을 한 번 지운다.
  - B. 남은 섹션은 무시: 이전 호환용 속성을 하나 남겨 `DawonRelay` 키를 값의 형태와 상관없이 읽고 버리며, 설정 파일을 다시 쓸 때 내보내지 않는다. 무시 동작을 확인하는 테스트를 더한다.
- 결정: A
- 이유: A는 코드가 가장 단순하고 지금 설정 읽기 규칙(모르는 키는 오류)을 그대로 두며, 실패해도 메시지에 키 이름이 나와 원인이 바로 보인다. 이 설정을 쓰는 곳은 이 서버뿐이라 줄 하나를 지우는 수고가 작다. B는 사용자가 설정을 손댈 필요는 없지만 없어진 기능의 흔적(속성·테스트)이 코드에 남아, 줄 하나를 지우는 수고에 비해 유지할 코드가 생긴다.
- 반영: spec.md C3
