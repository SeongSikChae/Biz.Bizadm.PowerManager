# 장치 MQTT 제어 기능 근거 문서 작성 작업

형식: `- [x] T001 [P] 설명 (파일 경로) — C번호`
`[P]`: 다른 파일을 고치고 끝나지 않은 작업에 의존하지 않아 다른 작업과 동시에 할 수 있음

분석 작업(단계 1)은 저장소 파일을 바꾸지 않는다. 산출물(디컴파일 로그 등)은 분석 서버 작업 폴더에 두고, 결과는 저장소 밖 작업 문서의 분석 메모에 적는다.

## 단계 1: 펌웨어 분석

- [x] T001 [P] 이미지 구조: 네 이미지의 세그먼트 배치(IROM·IRAM·DRAM 링크 주소·길이)와 SHA-256, 모델마다 `_1`·`_2` 재배치 비교, B540 두 이미지와 덤프 두 슬롯의 바이트 비교를 작업 문서 분석 메모에 적는다 (분석 서버 작업 폴더) — C1
- [x] T002 [P] M130-W `_1` 분석: 비교하는 `msg.o` 값 전부·번호·비교 순서·처리 함수와 하는 일, 오브젝트 분기 함수가 비교하는 오브젝트 번호 전부와 오브젝트마다 인스턴스·리소스 전부(오브젝트 99 포함), 리소스마다 받는 오퍼레이션·값 해석·저장 위치 또는 동작·읽기 응답, 처리 뒤 발행(토픽 접미·`msg.o`·요소 형식)을 디컴파일로 확인한다 (분석 서버 작업 폴더) — C2, C3, C4
- [x] T003 [P] B540 `_2` 오퍼레이션 분기: 비교하는 `msg.o` 값 전부·번호·비교 순서·처리 함수와 하는 일(`chg`·`reb` 포함)을 확인한다 (분석 서버 작업 폴더) — C2
- [x] T004 B540 `_2` 오브젝트 분기와 리소스: 오브젝트 분기 함수가 비교하는 오브젝트 번호 전부와 처리 함수, 오브젝트마다 인스턴스·리소스 전부, 리소스마다 받는 오퍼레이션·값 해석·저장 위치 또는 동작·읽기 응답을 확인한다. 오브젝트 99는 `b540-mqtt-topic.md` 결과와 대조만 한다 (분석 서버 작업 폴더) — C3
- [x] T005 B540 `_2` 제어 뒤 응답: 처리 뒤 발행 함수(토픽 접미·`msg.o`·요소 형식)를 확인한다 (분석 서버 작업 폴더) — C4

체크포인트: 작업 문서 분석 메모에 다음이 주소와 함께 있고, 밝히지 못한 것은 미확인과 까닭이 적혀 있다.
- 네 이미지의 배치·SHA-256, `_1`·`_2` 재배치 비교, B540 두 이미지와 덤프 두 슬롯의 바이트 비교
- 두 모델의 오퍼레이션 표(값·번호·비교 순서·처리 함수·하는 일)
- 두 모델의 오브젝트 번호 전부와 리소스마다 받는 오퍼레이션·값 해석·저장/동작·읽기 응답
- 두 모델의 제어 뒤 응답

## 단계 2: 새 근거 문서 작성

- [x] T006 머리말(이미지 네 개 항목, 도구·버전·날짜, 이미지별 배치 요약 표, 표기, 관련 문서, 실장비 버전 주의)과 1절(`_1`·`_2` 관계, 분석한 이미지와 주소 기준, 덤프 두 슬롯 비교, 기존 주소 사용 가능 여부)을 쓴다 (docs/reference/mqtt-device-control.md) — C1, C9
- [x] T007 3절 B540 1.01.34(오퍼레이션 분기 표, 오브젝트·리소스 표, 제어 뒤 응답)를 쓴다 (docs/reference/mqtt-device-control.md) — C2, C3, C4
- [x] T008 4절 M130-W 2.01.58(3절과 같은 구성, 오브젝트 99 포함)을 쓴다 (docs/reference/mqtt-device-control.md) — C2, C3, C4
- [x] T009 2절 제어 항목 요약 표(릴레이·재부팅·시간 동기·보고 조건·스케줄·알람·FOTA·자동 복구와 찾은 항목, 모델별 메시지·근거 표기·링크, 적용 펌웨어 버전)를 쓴다 (docs/reference/mqtt-device-control.md) — C5
- [x] T010 5절 모델 간 차이를 쓴다 (docs/reference/mqtt-device-control.md) — C6
- [x] T011 6절 기존 근거 문서와의 차이(`b540-mqtt-topic.md` 절·표 위치마다 바뀜·확정·보완, 없으면 없다고)를 쓴다 (docs/reference/mqtt-device-control.md) — C11
- [x] T012 7절 미확인과 실장비 확인 후보(보낼 메시지, 상태 변경 표시, 적용 펌웨어 버전, B540 버전 주의)를 쓴다 (docs/reference/mqtt-device-control.md) — C7

체크포인트: 새 문서에 plan 「인터페이스·데이터」의 머리말과 1~7절이 모두 있다.

## 의존 관계

- 단계 1 → 단계 2: 문서 내용이 분석 결과에서 온다. T001~T003은 서로 다른 자료를 보므로 동시에 할 수 있고, T004·T005는 T003의 처리 함수 주소가 필요하다.
- 단계 2 안: T009(요약 표)·T010(차이)·T011(기존 문서 차이)·T012(미확인)는 T006~T008의 내용을 모아 쓰므로 그 뒤에 한다.
- 단계 3: T013~T015는 서로 다른 파일이고 새 문서 링크·내용만 필요하므로 단계 2 뒤에 동시에 할 수 있다.
- 단계 4는 spec-driven 규칙대로 마지막 구현 단계로 둔다.
- 단계 5는 모든 변경 뒤에 한다.
