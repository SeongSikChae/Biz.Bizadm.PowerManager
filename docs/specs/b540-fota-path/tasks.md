# B540 FOTA 요청 경로 펌웨어 분석 작업

형식: `- [ ] T001 [P] 설명 (위치) — C번호`
`[P]`: 다른 작업과 동시에 할 수 있음

분석은 원격 Linux(`plink bizadm@20.214.104.36`)의 `/mnt/siem/b540-analysis`에서 한다. 주소는 작업 시 기존 `.dis` 기준(파일+`0x40180000`)으로 보고, 문서에는 참 링크 주소(파일+`0x40200000`)·DRAM vaddr로 적는다. 분석 산출물·덤프·실장비 값은 저장소에 넣지 않는다.

## 단계 1: 환경·진입점

- [x] T001 원격 환경을 확인한다 (원격 `/mnt/siem/b540-analysis`) — C1~C6
  - `/mnt/siem` 마운트, `xtensa-lx106-elf-objdump`·`appB-irom.dis`·`appB-iram.dis`·`xref.py`·`callers.py`·`b540-dump1.bin` 존재 확인
  - irom `.dis` 기준(`0x40201000`↔파일 `0x81000`)과 DRAM 매핑(seg3 `0x3ffe8db0`↔파일 `0xdeb5c`)을 알려진 값으로 재확인
- [x] T002 요청 생성 함수 진입점을 정한다 (원격) — C2, C3
  - `upgrade_start`·`upgrade_connect`(로그 문자열 파일 `0xd4cxx`) 주소가 리터럴 풀에 있는지(직접 참조) 확인한다.
  - 있으면 그 `l32r` xref로 진입점을 잡는다. 없으면 설정 파서(`.dis 0x4021d1a5` 부근)·`Set_UpgradeResourceData`가 채운 FOTA 버퍼를 쓰는 곳을 진입점으로 잡는다.

체크포인트: 환경이 있고, 요청 생성 흐름의 진입점을 하나 이상 잡았다.

## 단계 2: 추적

- [x] T003 URL 파싱을 밝힌다 (원격) — C1
  - `UpdateUrlParser`·설정 파서(`0x4021d1a5` 부근)에서 받은 URL/`LFota_Url`를 어떤 조각(스킴·호스트·포트·경로·버전)으로 나눠 어떤 버퍼(`gSysInfo.FotaUrl`·`GetFotaAddr`·`GetFotaPort`)에 넣는지 디스어셈블로 본다. 못 짚은 조각은 미확인.
- [x] T004 버전 요청 경로를 밝힌다 (원격) — C2
  - 진입점에서 `GET %s/version`을 쓰는 `sprintf`류의 `%s` 인자를 추적해 URL의 어느 부분인지 보이고, 가짜 장비의 `{URL}/version`과 같은지/다른지 판정한다. 못 정하면 미확인.
- [x] T005 이미지 요청 경로를 밝힌다 (원격) — C3
  - `GET %s%s`의 두 인자를 추적한다. 두 번째 조각에 파일 이름이 붙는지, 붙으면 어떻게 정해지는지(상수·버전·슬롯) 보이거나 미확인으로 남긴다.
  - T004·T005에서 베이스+오프셋·`sprintf` 데이터플로가 `objdump` 수동 판독으로 안 풀리면, 사용자에게 알린 뒤 Ghidra 12.2 + Xtensa 모듈을 원격에 설치해 디컴파일로 본다(D002).
- [x] T006 [P] 버전 비교 규칙을 밝힌다 (원격) — C4
  - `CheckVersion`·`checkVersionChar`·`AtoZParser`에서 `/version` 응답과 장치 버전을 어떻게 비교해 받기를 시작하는지 보이거나 미확인.
- [x] T007 [P] MQTT FOTA 수신을 밝힌다 (원격) — C5
  - `Set_UpgradeResourceData`가 받는 `/5/0/*` 리소스 번호와 `/5/0/1` 값을 URL로 쓰는지 보이거나 미확인.
- [x] T008 [P] 슬롯 A/B FOTA 코드 동일 여부를 본다 (원격) — C6, C7
  - 슬롯 A(파일 `0x5f66b` 부근)의 FOTA 형식 문자열·관련 함수 바이트를 슬롯 B와 비교해 FOTA 코드가 같은지 확인하고, 다르면 그 사실을 적는다(D003). 실제 활성 슬롯은 덤프로 단정하지 않는다.

체크포인트: C1~C5와 슬롯 A/B 비교(T008)가 관찰 또는 미확인으로 정해졌다.

## 단계 3: 종합·반영

- [x] T009 요청 경로 예를 종합한다 (작업 문서) — C6
  - 다원 URL `http://dwapi.dawonai.com:18446/DAWONDNS/B540_W/1.01.34`에 대해 장치가 보낼 실제 요청(버전·이미지)의 경로 예를 적는다. 미확인이 남으면 무엇이 비어 경로를 확정 못 하는지 적는다. 가짜 장비가 보낸 경로와의 차이(있으면)를 밝힌다.
- [x] T010 기준 분석 기록에 반영한다 (docs/reference/b540-fota.md) — C7
  - 3절 업데이트 흐름의 URL 파싱·요청 경로를 분석 결과로 고치고, 4절 슬롯 이미지 이름·5절 미확인 항목을 갱신한다.
  - 관찰·추정·미확인 표기와 근거(함수 참 링크 주소·형식 문자열 DRAM 주소·파일 오프셋)를 붙인다.
  - 다원 서버 호스트·포트는 그대로 적고, 실장비 mac·계정·키와 덤프 경로·원격 산출물 경로는 넣지 않는다.

체크포인트: `b540-fota.md`에 C1~C6 결과가 근거와 함께 반영됐다.

## 단계 4: 검증

- [x] T011 반영을 검증한다 (docs/reference/b540-fota.md) — C7(수동 확인)
  - 반영 내용이 T003~T009 분석 결과와 맞는지, 관찰/추정/미확인 표기와 근거 주소가 붙어 있는지, 서버 호스트·포트만 그대로이고 실장비 값·덤프 경로가 없는지 본다.

체크포인트: 반영 내용과 분석 결과가 일치한다.
