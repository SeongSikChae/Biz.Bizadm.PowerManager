# 서버 주입 메시지 해석 불가 토픽 로그 제외 결정

### D001 C1 테스트는 R5와 R12(또는 R13) 로그가 모두 보인 뒤 R7 없음을 본다
- 단계: tasks
- 질문: tasks 검토 2회차 지적 1. T002 둘째 항목(구독자 없음)은 plan.md 「바꿀 파일·구조」에 없는 R5 로그(`Time sync response sent`) 확인을 더했고, 이 확인을 R13 로그가 나타날 때까지 기다린 뒤 하게 했다. R5 로그는 `LoggingDeviceMessageHandler`에서 `InjectApplicationMessage`의 await가 끝난 뒤 쓰이고, R13 로그는 그 주입 안의 분배(`DispatchApplicationMessage`)에서 쓰이므로 R13 줄이 보인 직후에는 R5 줄이 아직 없을 수 있어 테스트가 간헐적으로 실패한다. 구독자 있음 항목도 응답을 받은 직후 로그를 읽어 같은 위험이 있다. plan.md 검증 전략은 C1에 R5·R12·R13 로그가 모두 있는지 보라고 한다.
- 선택지:
  - A. 필요한 로그 모두 기다림: T002 두 항목 모두 R5 줄과 R12 줄(구독자 있음) 또는 R13 줄(구독자 없음)이 다 나타날 때까지 기다린 뒤 R7 줄이 없는지 본다. R5가 가장 늦게 쓰이므로 그때는 R7 판정도 할 수 있다.
  - B. 구독자 없음에서 R5 빼기: 구독자 없음 항목은 R13 줄이 나타난 뒤 R7 줄이 없는지만 본다. 구독자 있음 항목은 그대로 둔다.
  - 고치지 않음: T002를 그대로 둔다.
- 결정: A
- 이유: A는 간헐 실패를 없애고 spec C1의 "R5 응답 로그도 지금처럼 남는다"를 두 경우 모두 확인하며 plan.md 검증 전략과 맞는다. B는 구독자 없음 쪽 간헐 실패는 없애지만 구독자 있음 항목의 R5 확인이 여전히 타이밍에 기대고, 구독자가 없을 때의 R5 유지를 확인하지 않는다. 고치지 않음은 실제로 일어날 수 있는 간헐 실패가 남고 plan.md와도 어긋난다.
- 반영: tasks.md T002
